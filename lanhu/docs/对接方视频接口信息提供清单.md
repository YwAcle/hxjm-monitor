# 对接方视频接口信息提供清单

## 一、文档说明

本文档用于收集第三方设备或平台的视频流接入信息，供视频推流服务、AI 算法服务和前端页面进行联调。

当前系统的标准视频链路为：

```text
第三方设备/平台视频流
        ↓
mtx 视频推流处理服务
        ↓
MediaMTX 流媒体服务器
        ↓
WebRTC/WHEP
        ↓
lanhu 前端页面展示
```

浏览器不能直接播放 RTSP 地址。对接方应优先提供可访问的 RTSP 视频流地址；系统接入后会转换为 WebRTC/WHEP 地址供前端播放。

| 字段 | 填写内容 | 示例 |
|---|---|---|
| RTSP 地址 |  | `rtsp://192.168.1.100:554/Streaming/Channels/101` |
| RTSP 用户名 |  | `admin` |
| RTSP 密码 |  | `********` |
| RTSP 端口 |  | `554` |
| 是否支持 TCP 拉流 |  | 是/否 |

| 视频编码 |  | H.264 / H.265 / MJPEG |

RTSP 地址示例：


请注意：如果密码包含 `@`、`#`、`:`、`/` 等特殊字符，需要进行 URL 编码，或单独提供用户名、密码和视频路径。

## 三、如果不是 RTSP 接口

如果对方无法提供 RTSP，而是提供 HTTP、HTTPS 或其他视频接口，请完整填写以下信息：

| 字段 | 填写内容 | 示例 |
|---|---|---|
| 接口完整地址 |  | `https://example.com/api/video/live` |
| 请求方式 |  | GET / POST |
| 请求参数 |  | `deviceId=001` |
| Header 参数 |  | `Authorization: Bearer xxx` |
| Token 获取方式 |  | 登录接口 / 固定 Token |
| Token 有效期 |  | 24 小时 |
| 返回类型 |  | HLS / FLV / MJPEG / WebRTC / MP4 |
| Content-Type |  | `application/x-mpegURL` |
| 是否支持跨域 |  | 是/否 |
| 是否支持断线重连 |  | 是/否 |
| 是否有调用频率限制 |  | 每分钟 60 次 |

同时请提供一份完整的请求示例和返回示例。

```bash
curl -v -X GET 'https://example.com/api/video/live?deviceId=001' \
  -H 'Authorization: Bearer <token>'
```

如果返回的是普通图片、单个 MP4 文件或业务 JSON，而不是连续视频流，需要对方提供视频流转换方案或可持续读取的流媒体地址。

## 九、我方接入验证步骤

收到资料后，我方按以下顺序验证：

### 1. 验证网络

```bash
ping <设备IP>
nc -vz <设备IP> <端口>
```

### 2. 验证 RTSP 视频

```bash
ffprobe -rtsp_transport tcp '<RTSP地址>'
ffplay -rtsp_transport tcp '<RTSP地址>'
```

### 3. 启动 mtx 算法任务

调用：

```http
POST /internal/v1/cameras/{cameraId}/tasks
```

请求体示例：

```json
{
  "task": "deepsort",
  "inputUrl": "rtsp://<设备RTSP地址>",
  "outputUrl": "rtsp://mediamtx:8554/live/camera_1_deepsort"
}
```

### 4. 验证输出流

```bash
ffplay -rtsp_transport tcp \
  rtsp://<服务器IP>:8554/live/camera_1_deepsort
```

### 5. 前端展示

前端使用以下地址进行 WebRTC/WHEP 协商：

```text
http://<服务器IP>:8889/live/camera_1_deepsort/whep
```

前端不能把 `rtsp://...` 直接设置给 `<video src>`。

## 十、最少必须提供的内容

如果对方只需要提供最少资料，至少包括：

1. 设备唯一编号。
2. 可访问的 RTSP 地址。
3. RTSP 用户名和密码。
4. 设备 IP、端口和网络访问方式。
5. 视频编码、分辨率和帧率。
6. 是否需要音频。
7. 是否需要 AI 算法处理。
8. 测试账号有效期和技术联系人。
