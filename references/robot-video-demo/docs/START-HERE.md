# 四路版首次操作：VS Code 点击运行

## 已在原电脑上配置过环境

1. 在 VS Code 选择“文件 → 打开文件夹”，打开整个 robot-video-demo 文件夹，不只是某个 HTML。
2. 确认安装 Microsoft Python 和 Python Debugger 扩展；本项目已包含扩展推荐。
3. 按 Ctrl+Shift+P，选择 Python: Select Interpreter。
4. 优先选择项目 .venv。如果尚未创建，可以选择原来的 `C:\Users\wxl48\Documents\Codex\2026-09-20\suo\robot-console\.venv\Scripts\python.exe`，该环境已有依赖。
5. 点击左侧“运行和调试”，下拉选择 **四路模拟监控（先运行这个）**，按 F5。或打开 run_demo.py，点击右上角“运行 Python 文件”。
6. 浏览器打开 http://127.0.0.1:8890/。
7. 确认四个窗口显示不同色相和白框位置的测试视频、在线数 4 / 4、各路解码帧数增加。
8. 点击任意一路“停止”，其余三路应继续播放；点击该路“连接”可恢复。页面的“停止全部”不关闭后台服务。
9. 视频上方现有机器狗、机械臂两个状态面板。模拟模式每秒刷新心跳，约每 4 秒演示一个步骤；“移动”表示相对目标垃圾调整最终抓取位置。模拟标签不代表已接通实物。

如果已有单路旧服务在运行，先在其启动终端按 Ctrl+C，确保不是重复启动占用同一端口。

## 新电脑 / 重新解压的文件夹

需先安装 Python 3.12，并在 VS Code“终端 → 新建终端”执行一次：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tools/install_tools.py
```

完成后选择新建的 .venv 解释器，按前面的 F5 步骤运行。源码包没有包含运行工具、虚拟环境和设备密码。

## 改成真正的四个摄像头

1. 在左侧打开 cameras.json，核对四路的 name 与 source。
2. M20 前后摄使用 m20，分别指定 camera=front/back，url 为空时使用给定的默认 IP/端口。
3. 第三、四路如果已有 RTSP 地址，将 source 改为 rtsp 并填写各自 url。
4. 如果是 D435/D455 的 USB 或 ROS 图像，保留 publisher，让采集程序分别发布到 live/camera_3 和 live/camera_4。驱动和采集端未配置时会显示等待。
5. 暂时不接的通道，source 可改为 disabled。
6. 保存配置。在启动终端按 Ctrl+C 停止模拟，再在“运行和调试”下拉选择 **四路实物监控（读取 cameras.json）**，按 F5。
7. 刷新网页，确认模式标签为实物，分别在四个镜头前移动物体，核对通道没有接反。
8. 实物设备状态需要另外对接，初始“待接入”属正常现象。按 [状态接口说明](INTERFACES.md#设备实时状态接口) 将 SDK/ROS 真实状态映射后上报。视频正常不会自动点亮设备状态；超过 5 秒没有新状态会提示过期。

首次不要同时改变摄像头协议、网络和前端。先确认一台实物的取流，再扩成四台，最后测试跨电脑和 Tailscale。

## 需要向厂家确认

| 信息 | 当前已知与待确认 |
|---|---|
| M20 视频格式 | 给定客户端为 24 字节包头 + H.264，通过 WebSocket 接收 |
| IP/端口/路径 | 默认 192.168.126.176:8765，/front 和 /back；实际值需确认 |
| 视频服务启动 | 需厂家给操作；遥控器有画面不能证明服务已开放 |
| 并发能力 | 前后相机、遥控器和外部客户端能否同时使用待确认 |
| 帧率和编码 | 默认 25 FPS 为假设，需确认真实值和浏览器兼容性 |
| D435/D455 | 接在哪台主机、系统、USB/驱动/SDK/ROS 话题、序列号均需确认 |

## 使用完成后

在运行终端按 Ctrl+C，整套服务停止，网页地址随之不能访问。不要只关闭页面后以为后台采集也停了。若直接强制结束调试器导致下次端口占用，先确认残留进程归属，再处理；优先用 Ctrl+C 正常退出。

完整端口、来源配置示例、Linux 和现有 lanhu 接入方式见项目 README。
