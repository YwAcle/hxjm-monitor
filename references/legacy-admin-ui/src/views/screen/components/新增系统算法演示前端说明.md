# 前端新增算法集成指南

## 概述

本文档详细说明如何在前端系统中添加新的算法支持。整个过程包括API接口定义、组件方法实现和UI交互设计三个主要部分。

## 1. API接口定义

在 `src/api/algorithm/index.js` 文件中添加新算法的API函数：

```javascript
// 运行新算法
export function runNewAlgorithm(data) {
  return request({
    url: `${algorithmServiceUrl}/api/new_algorithm/start-algorithm`,
    method: 'post',
    data: data,
    timeout: 60000
  })
}

// 停止新算法
export function stopNewAlgorithm(streamIds) {
  return request({
    url: `${algorithmServiceUrl}/api/new_algorithm/stop-algorithm`,
    method: 'post',
    data: { stream_ids: streamIds },
    timeout: 60000
  })
}
```

注意：
- 确保API路径与后端实际接口路径一致
- 参考后端API文档确定请求参数格式
- 根据算法特性设置适当的超时时间

```javascript
// 处理新算法
handleNewAlgorithm() {
  this.uploading = true
  this.videoSrc = [] // 清空之前的视频源
  console.log('新算法请求设备:', this.selectedMachines)
  
  // 准备请求数据

    machineList: this.selectedMachines.map(machine => ({
      machineId: String(machine.machineId),
      videoUrl: machine.videoUrl,
      resolution: machine.resolution || '1920x1080',
      codec_type: machine.decoder || 'h264'
    }))
    // 根据算法需求添加其他参数
  }

  // 使用封装的API方法
  runNewAlgorithm(requestData)
    .then(response => {
      if (response.code === 200) {
        this.$message.success('新算法启动成功')
        // 处理返回的视频流
        if (response.data && Array.isArray(response.data.machines)) {
          // 添加详细日志
          console.log('新算法返回的完整数据:', response.data);
          
          // 从返回数据中提取 rtmpUrl
          this.videoSrc = response.data.machines.map(item => {
            console.log('获取到的RTMP地址:', item.rtmpUrl);
            return item.rtmpUrl;
          });
          
          this.streamType = this.videoSrc.map(url => {
            const type = this.determineStreamType(url);
            console.log('流地址:', url, '判断的类型:', type);
            return type;
          });

          // 保存机器ID和状态信息，用于后续停止操作
          this.newAlgorithmStatus = response.data.machines.map(item => ({
            machineId: item.machineId,
            status: item.status,
            streamId: item.streamId // 保存streamId
          }))
        } else {
          this.$message.warning('未收到视频流数据')
          this.uploading = false
        }
      } else {
        this.$message.error(response.msg || '新算法启动失败')
        this.uploading = false
      }
    })
    .catch(error => {
      this.uploading = false
      this.$message.error('新算法请求失败: ' + error.message)
    })
}
```

## 3. 常见问题处理

### 3.1 接口返回422错误

如果遇到接口返回422 Unprocessable Entity错误，通常是因为请求数据不符合后端API的预期格式：

1. **检查API路径**：确保前端请求的URL路径与后端实际接口路径一致
2. **检查请求数据结构**：确保请求数据的格式与后端API的预期格式匹配
3. **检查字段类型**：确保字段类型正确，例如将数值型ID转换为字符串
4. **添加调试日志**：在请求前添加`console.log`输出完整请求数据，便于调试

### 3.2 视频流无法显示

如果算法成功启动但视频流无法显示，可能的原因包括：

1. **RTMP地址格式问题**：检查VideoPlayer.vue中对RTMP地址的处理逻辑
2. **跨域问题**：确保前端可以访问流媒体服务器
3. **播放器兼容性**：检查浏览器是否支持相应的流媒体格式

## 4. 后端接口要求

新算法的后端接口通常需要满足以下格式：

### 启动接口

- 路径：`/api/new_algorithm/start-algorithm`
- 方法：POST
- 请求体格式：
```json
{
  "machineList": [
    {
      "machineId": "1",
      "videoUrl": "rtsp://example.com/stream",
      "resolution": "1920x1080",
      "codec_type": "h264"
    }
  ]
}
```

- 响应格式：
```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "machines": [
      {
        "machineId": "1",
        "status": "running",
        "streamId": "stream_123",
        "rtmpUrl": "rtmp://example.com/live/stream_123"
      }
    ]
  }
}
```

### 停止接口

- 路径：`/api/new_algorithm/stop-algorithm`
- 方法：POST
- 请求体格式：
```json
{
  "stream_ids": ["stream_123"]
}
```

- 响应格式：
```json
{
  "code": 200,
  "msg": "success"
}
```

4. 实现算法处理方法
5. 修改handleRun方法添加新算法判断
