## 使用 Address Sanitizer（ASan）
### annexb 忘记扩容
cmake 中添加
```
set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -fsanitize=address")
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -fsanitize=address")
```

然后提示
```
READ of size 64 at 0x6040003aaec0
0x6040003aaec0 is located 0 bytes after 48-byte region 
[0x6040003aae90,0x6040003aaec0)

越界发生位置
#0 memcpy
#1 libavcodec
#2 H264FrameHook.cpp:137
```
然后查看对应 decoder 代码，发现问题出在 annexb组包
```c++
if (frame->prefixSize() == 0 && frame->size() > 0) {  
	//这里本来没有+4，导致我写了 4 字节后长度不对，导致越界
    annexb.resize(frame->size()+4);  
    annexb[0] = 0; annexb[1] = 0; annexb[2] = 0; annexb[3] = 1;  
    memcpy(annexb.data() + 4, frame->data(), frame->size());  
    data = annexb.data();  
    dataSize = (size_t)annexb.size();  
}
```
很多 ZLMediaKit 回调给你的 Frame 不一定包含 start code，有的 length 只有几十字节。你要补 4 字节 00 00 00 01，但 **忘了扩容**。

### annexb 的包，来自av_parse_parse2 处理，需要扩容
- av_parser_parse2 会在输入末尾额外读取 AV_INPUT_BUFFER_PADDING_SIZE 个字节
```
// av_parser_parse2 会在输入末尾额外读取 AV_INPUT_BUFFER_PADDING_SIZE 个字节，  
// 因此必须保证输入缓冲区尾部有足够的 0 填充，否则 ASan 会在 av_parser_close 内报错。  
std::vector<uint8_t> annexb;  
const size_t extra_prefix = (frame->prefixSize() == 0 && frame->size() > 0) ? 4 : 0;  
annexb.resize(frame->size() + extra_prefix + AV_INPUT_BUFFER_PADDING_SIZE, 0);  
size_t copy_offset = extra_prefix;  
if (extra_prefix) {  
    annexb[0] = 0; annexb[1] = 0; annexb[2] = 0; annexb[3] = 1;  
}  
memcpy(annexb.data() + copy_offset, frame->data(), frame->size());  
// padding 已经在 resize 时置 0const uint8_t * data = annexb.data();  
size_t dataSize = annexb.size() - AV_INPUT_BUFFER_PADDING_SIZE;
```
### ffmpegTool 多线程竞争，导致avcodeccontext 竞争
- 解决：给 decoder thread 和 encoder thread 都弄一个 ffmpegTool
### 流开的线程太多，导致崩溃？
- 解决：将每个流的线程数，从 n 改成 n/流数，就好了
- 本质：sws、hw 、ffmpeg 初始化，这些都不是线程安全的，本质是对 ffmpeg 内部并发的不理解。以前为 n 时，会报错
```c++
mmco: unref short failure
illegal short term buffer state detected
reference picture missing during reorder
```
- 上述表明，ffmpeg h264 引擎内部被并发破坏
