# 登记库主动行人检索最小接入

本版本只读 `reid_target` 的有效记录，默认复用登记图片在本机提取 OSNet 特征，不修改表结构、身份关联或已有向量。不访问实时摄像头，不把登记照片当作历史出现证据。第一版仅支持本次上传的单人裁剪图，不做多人检测或自动裁剪。

## 工具与验证范围

- `search_pedestrians_by_image`：默认使用本地 OSNet 对查询图片和登记图片提取512维特征，在最多 2000 条有效登记记录中精确计算余弦相似度，默认返回前 5 个候选。登记库原有3072维 CLIP-ReID 特征不参与本地比较。保留远程兼容特征模式作为可选项。没有校准阈值，因此返回的是候选，不做确定身份判断。
- `search_pedestrians_by_description`：用现有视觉模型按衣着、颜色、携带物品筛选登记照片。最小原型只检查按 ID 排序的前 64 条有效登记记录；跳过无效图片，结果返回 `gallery_truncated`、`searched_count`、`skipped_count`。它不是文本 ReID 向量检索，没有数值相似度。空结果仅代表本次检查的图片未匹配；登记照片中的衣着可能已过时。

描述检索不需要新增描述字段或缓存，代价是每次需要一次多图视觉模型请求。每页拼图包含最多16张带编号的行人缩略图，64条记录最多4页，适配当前配置的一次最多4张输入图片。当前41条记录需要3页。拼图会降低小物品的可辨识度，第一版仅验证明显外观。模型必须支持多图片输入；不支持时工具报错。

## 默认本地模式：安装与验证

模型为 `OSNet x0.25 MSMT17`，采用 ONNX Runtime CPU 推理，不加载 PyTorch，不使用聊天模型的 GPU。权重约0.91 MB，来源为 [anriha/osnet_x0_25_msmt17](https://huggingface.co/anriha/osnet_x0_25_msmt17)，发布页标注 MIT；OSNet 上游项目为 [deep-person-reid](https://github.com/KaiyangZhou/deep-person-reid)。下载器固定发布版本 `1e22b925c70caa5591e9fab3f5540af8484bcad8` 并校验 SHA-256：`e78604f4ccda49b8f41cd0f8f7303800ce75d2361895ebb0729513c1bf53d277`。

从仓库根目录运行，使用 Agent 实际运行的 Python：

```bash
/data1/userhome/va/miniconda3/envs/monitor/bin/python -m pip install -r llm_agent_service/requirements-reid.txt
/data1/userhome/va/miniconda3/envs/monitor/bin/python scripts/setup_local_reid.py

# 使用现有配置加载方式，避免直接 source 任意 .env 内容。
source scripts/load_env.sh
load_env_defaults .env
/data1/userhome/va/miniconda3/envs/monitor/bin/python scripts/verify_local_reid.py
# 或指定实际查询图片：
/data1/userhome/va/miniconda3/envs/monitor/bin/python scripts/verify_local_reid.py --image /本仓库内/行人图片.jpg
```

权重位于 `.runtime-cache/reid/osnet_x0_25_msmt17.onnx`，不进入 Git。代码默认 `REID_BACKEND=local`，无需配置远程 URL。可用 `REID_MODEL_PATH`（启动参数 `--reid-model-path`）指定兼容的 OSNet ONNX 文件，推理输出要求512维。首次图片查询时延迟加载模型，按 RGB、256×128、ImageNet mean/std 预处理，适配固定16张的模型批量；尾批用复制图片补齐，只返回有效位置。推理使用2个CPU线程。

登记特征保存在 Agent 进程内，按人员 ID 和图片内容哈希复用；图片变更重新编码，人员停用/移除后在下次查询删除缓存。进程重启会重新编码，不向原数据库写入缓存，不需要额外缓存服务。不同进程分别持有缓存；如替换模型文件，需要重启 Agent。模型版本结果中带权重哈希和预处理版本。

代码更新后需重启原有 Agent 进程才会加载本地模式。聊天入口仍需要现有聊天模型正常运行，但独立验证脚本完全不需要远程 ReID 或聊天模型。文字描述工具仍依赖视觉聊天模型，本次本地 OSNet 只接管图片检索。

## 可选远程模式的最小接口

需要复用原3072维特征时，才切换远程模式（已有启动脚本会加载根目录 `.env`）：

```dotenv
REID_BACKEND=remote
REID_EMBEDDING_URL=http://模型服务器:端口/embed
REID_EMBEDDING_MODEL=与数据库 embedding_model 完全一致的版本标识
REID_TIMEOUT_S=15
```

也支持启动参数 `--reid-embedding-url`、`--reid-embedding-model`、`--reid-timeout-s`。URL 是完整 POST 地址，不会自动追加路径。目前接口客户端无鉴权配置；若原服务有鉴权或其他协议，需要相应适配后再接入。

请求 JSON：

```json
{
  "image_base64": "data:image/jpeg;base64,...",
  "embedding_model": "CLIP-ReID-ResNet50"
}
```

响应 JSON：

```json
{
  "embedding_model": "CLIP-ReID-ResNet50",
  "embedding": [0.1, 0.2, 0.3]
}
```

示例向量仅展示协议，实际维度必须与库中向量一致。模型端必须复用生成库中特征时的权重、预处理、输出层和特征组合；不能仅修改模型名称来兼容。Agent 校验响应模型名、向量有效性及与每条登记特征的维度，并进行 L2 归一化后计算余弦相似度。

远程模式未配置接口返回 `status=not_configured`，不执行图片匹配；没有兼容特征返回 `no_compatible_features`，不能解释为“未找到此人”。本地和远程特征空间完全分开，不会用 aHash 或通用 CLIP 特征替代。

## 聊天请求与结果

保持现有接口：向 `POST /chat` 或 `POST /chat/stream` 提交 `prompt`、`image` 和 `session_id`。

图片提示示例：“用这张单人图片找相似的登记行人，返回前3个候选。”

文字提示示例：“在登记照片中找穿红色上衣、背黑色包的人。”

工具图片参数由执行器使用本次上传图片强制注入，不允许模型生成 Base64。查询图片不持久化，不支持下一轮直接引用上次图片。

普通 `/chat` 返回 `data.type=pedestrian_search`，候选在 `data.candidates` 中，每项包含 `person_id`、`name`、`employee_id`、`image_base64`，图片检索附 `similarity`，文字检索附 `match_reason`。这里展示的姓名只是候选登记档案的姓名，不是对查询图片人物身份的确认。

SSE 在正文 `delta` 结束后、`done` 前增加 `result` 事件，其数据为上述工具结果，供前端渲染候选卡片。Base64 保留在业务结果中，但不会加入工具观察文本或日志。现有前端如果只处理 `delta`，需要增加 `result` 事件处理才能显示图片。

## 上线前验证

2026年10月20日本地模型与在线数据库实测：41条有效记录均成功重新编码为512维特征，一张登记照片自身查询排第一、余弦相似度1.0；前5张登记照片经0.85倍亮度调整及JPEG重编码后查询，原记录均排第一。首次加载、编码登记库和查询约0.97秒，缓存后每次约0.25～0.27秒（包含数据库读取）。这些测试只验证链路及轻微变换，不代表跨摄像头或跨姿态准确率。原库3072维特征未修改。

真实数据库 + 真实本地 ONNX 模型通过 Flask 测试客户端分别验证 `/chat` 与 `/chat/stream`，均返回3个候选且自身记录排第一；聊天工具决策使用模拟响应。相关自动化测试126项通过。检查时配置的聊天模型与 Agent 端口均未运行，因此尚未验证真实聊天模型自动选工具、文字视觉匹配或浏览器展示，需启动服务后联调。

1. 只读检查在线库的有效记录数、`embedding_model`、`vector_dims(embedding)` 和图片完整性。仓库 SQL 是截断样例，不能证明在线数据可用。
2. 从库中取一张图片作为查询，运行本地验证脚本，应能将自身记录排到前列。该测试验证特征和链路兼容性，不代表跨视角检索质量。
3. 换同一人的不同视角图片及其他人的图片，人工检查候选排序；未校准前不展示“身份置信度百分比”。
4. 用明确可见的衣着描述验证文字筛选，检查 `gallery_truncated` 的提示和前端照片展示。

如需历史轨迹、实时位置或录像，后续再按选中候选 ID 查询；本次最小工具不支持时间/摄像头过滤，不应静默丢弃用户这些条件后声称完成查询。
