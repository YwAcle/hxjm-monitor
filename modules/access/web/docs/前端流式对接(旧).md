# Agent 流式接口对接111

## 接口

`POST /chat/stream`

该接口使用 Server-Sent Events（SSE）返回响应。服务会先在后端完成 Agent 决策、时间解析和只读工具查询；浏览器只会收到最终用户答复的自然语言片段，绝不会收到 Agent 推理、动作 JSON、工具名、工具参数或原始工具结果。

现有的 `POST /chat` 保持不变，仍返回完整 JSON，适合不需要逐字展示的调用方。

## 请求

请求头：

```http
Content-Type: application/json
Accept: text/event-stream
X-Session-ID: browser-session-1
X-Trace-ID: trace-20260917-001
```

`session_id` 和 `trace_id` 也可以放在请求体中；请求体中的值优先。`session_id` 用于多轮对话，未提供时由服务生成。`trace_id` 用于排查请求，未提供时由服务生成。

```json
{
  "prompt": "最近一次异常是什么？",
  "session_id": "browser-session-1",
  "trace_id": "trace-20260917-001",
  "image": "data:image/png;base64,..."
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `prompt` | 否 | 用户问题；没有图片时必填。 |
| `image` | 否 | 单张图片的 Data URL 或 Base64；与普通 `/chat` 的图片限制一致。 |
| `session_id` | 否 | 1-128 位，允许字母、数字、`. _ : -`。 |
| `trace_id` | 否 | 1-128 位，允许字母、数字、`. _ : -`。 |

接口只接受 JSON 请求体，不支持 `multipart/form-data` 上传文件。需要流式处理图片时，前端应先将图片编码为 Base64/Data URL 后填入 `image`。

`/chat/stream` 的响应只包含最终自然语言，不返回超分图片、回放链接或其他结构化工具数据。前端需要展示超分结果等富媒体内容时，应继续调用原有的 `POST /chat`。

## SSE 事件

响应头包含：

```http
Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no
X-Trace-ID: trace-20260917-001
```

每个事件的 `data` 都是 JSON。

| 事件 | 数据 | 前端处理 |
| --- | --- | --- |
| `status` | `{"stage":"processing"}` | 显示“正在查询”。此时 Agent 正在执行规则和工具，尚无可展示正文。 |
| `status` | `{"stage":"generating"}` | 显示“正在生成回复”。之后会陆续收到 `delta`。 |
| `delta` | `{"text":"..."}` | 将 `text` 直接追加到当前机器人消息。 |
| `done` | `{"session_id":"...","finish_reason":"final","steps":2}` | 标记当前消息完成，保存 `session_id` 供下一轮复用。 |
| `error` | `{"error":"处理请求失败","error_code":"INTERNAL_ERROR"}` | 停止加载并显示稳定错误文案。 |

示例：

```text
event: status
data: {"stage":"processing"}

event: status
data: {"stage":"generating"}

event: delta
data: {"text":"最近一次异常是火灾，"}

event: delta
data: {"text":"发生在 camera_4 摄像头，时间为 2026年08月22日 23时07分10秒。"}

event: done
data: {"session_id":"browser-session-1","finish_reason":"final","steps":2}
```

`delta.text` 已是面向用户的中文自然语言。时间会按北京时间表达；前端不要自行将其转换为 ISO 时间或时区偏移格式。

## 浏览器调用示例

原生 `EventSource` 只能发送 GET 请求，不能携带本接口需要的 POST JSON。因此使用 `fetch` 读取响应流。

```ts
type StreamEvent =
  | { event: "status"; data: { stage: "processing" | "generating" } }
  | { event: "delta"; data: { text: string } }
  | { event: "done"; data: { session_id: string; finish_reason: string; steps: number } }
  | { event: "error"; data: { error: string; error_code: string } };

export async function streamChat(
  prompt: string,
  sessionId: string | undefined,
  onEvent: (event: StreamEvent) => void,
  signal?: AbortSignal,
) {
  const response = await fetch("/chat/stream", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Accept": "text/event-stream",
    },
    body: JSON.stringify({ prompt, session_id: sessionId }),
    signal,
  });

  if (!response.ok || !response.body) {
    const body = await response.json().catch(() => ({}));
    throw new Error(body.error || `请求失败：HTTP ${response.status}`);
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8");
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    let separator: number;
    while ((separator = buffer.indexOf("\n\n")) >= 0) {
      const frame = buffer.slice(0, separator);
      buffer = buffer.slice(separator + 2);
      const eventName = frame.match(/^event:\s*(.+)$/m)?.[1];
      const dataText = frame.match(/^data:\s*(.+)$/m)?.[1];
      if (!eventName || !dataText) continue;
      onEvent({ event: eventName, data: JSON.parse(dataText) } as StreamEvent);
    }
  }
}
```

调用时创建一条空的机器人消息；每收到一个 `delta` 就追加 `data.text`。收到 `done` 后，将其 `session_id` 保存到当前会话。用户取消生成时调用 `AbortController.abort()`；前端应保留已经展示的正文，并将该消息标记为已停止。

## 错误处理

请求在开始 SSE 前就能判断的错误会返回普通 JSON HTTP 响应，例如 `400 MISSING_PROMPT`、`400 INVALID_SESSION_ID`、`413 IMAGE_TOO_LARGE`。一旦已经返回 `text/event-stream`，后续执行异常会通过 `error` SSE 事件返回，HTTP 状态仍为 `200`；前端必须同时处理 HTTP 错误和 SSE 的 `error` 事件。
