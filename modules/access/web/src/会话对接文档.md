# LLM Agent Service 前端会话接入开发文档

> 文档日期：2026-09-11  
> 适用服务：`llm_agent_service`  
> 默认服务地址：`http://<AGENT_HOST>:8002`

## 1. 改动目标

`llm_agent_service` 已支持基于 LangChain 消息历史的短期会话记忆。前端需要为每个聊天会话维护一个稳定的 `session_id`，并在该会话的每次请求中重复传入。

接入完成后，可以实现以下效果：

```text
第一轮：用户说“我叫张三”
第二轮：用户问“我叫什么名字？”
模型能够结合第一轮消息回答“张三”
```

前端需要负责：

1. 为每个聊天会话维护唯一的 `session_id`。
2. 调用 `/chat` 时传入当前 `session_id`。
3. 保存后端响应中的 `session_id`。
4. 新建会话时切换到新的 `session_id`。
5. 切换历史会话时恢复对应的 `session_id`。
6. 清空上下文时调用后端记忆清理接口。

## 2. 后端接口概览

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/chat` | 文本或图片聊天 |
| `DELETE` | `/sessions/<session_id>/memory` | 清空指定会话的后端记忆 |
| `GET` | `/health` | 检查 Agent Flask 进程是否存活 |
| `GET` | `/ready` | 检查数据库和 SGLang 是否可用 |

注意：文本和图片统一使用 `/chat`，不存在单独的 `/chat_with_image` 接口。

## 3. Session ID 约定

### 3.1 格式要求

`session_id` 必须满足：

- 长度为 1 到 128 个字符。
- 允许英文字母、数字、`.`、`_`、`:` 和 `-`。
- 推荐直接使用 UUID。

合法示例：

```text
4ff025d5-116d-4180-a88f-8781d2f04350
browser-001
user_1001:chat_27
```

非法示例：

```text
用户 001
chat/001
包含空格
```

### 3.2 生成策略

推荐优先级：

1. 前端已有聊天会话 ID时，直接将该 ID作为 `session_id`。
2. 前端没有会话系统时，使用 `crypto.randomUUID()` 生成。
3. 也可以在第一轮不传，使用后端生成并返回的 ID。

前端生成示例：

```typescript
const sessionId = crypto.randomUUID();
```

禁止所有用户共用固定值：

```typescript
// 错误：可能造成不同用户的上下文串线
const sessionId = "default";
```

### 3.3 后端读取位置

后端按照以下顺序读取 `session_id`：

1. JSON 请求体中的 `session_id`。
2. `multipart/form-data` 中的 `session_id`。
3. URL 查询参数中的 `session_id`。
4. `X-Session-ID` 请求头。
5. 都未提供时由后端自动生成。

推荐在 JSON 或 `FormData` 请求体中显式传递，避免多标签页或多会话场景下使用了错误的全局请求头。

## 4. 数据类型定义

建议增加以下 TypeScript 类型：

```typescript
export type AgentResponseType =
  | "normal"
  | "reid"
  | "vad"
  | "super_resolution";

export interface AgentChatRequest {
  session_id?: string;
  prompt: string;
  image?: string;
}

export interface AgentChatResponse {
  session_id: string;
  type: AgentResponseType;
  text?: string;
  summary?: string;
  navigate_to?: string;
  page_index?: number;
  tracklet?: Record<string, number>;
  data?: Record<string, unknown>;
  time_range?: {
    label: string;
    start_ts: string;
    end_ts: string;
  };
  person_names?: string[];
  person_ids?: string[];
}

export interface AgentErrorResponse {
  error: string;
}

export interface ClearMemoryResponse {
  status: "ok";
  session_id: string;
  cleared: boolean;
}
```

## 5. 文本聊天接入

### 5.1 请求示例

```http
POST /chat
Content-Type: application/json

{
  "session_id": "browser-001",
  "prompt": "我叫张三"
}
```

### 5.2 响应示例

```json
{
  "session_id": "browser-001",
  "type": "normal",
  "text": "你好，张三。"
}
```

### 5.3 Fetch 封装

```typescript
const AGENT_BASE_URL = import.meta.env.VITE_AGENT_BASE_URL
  ?? "http://127.0.0.1:8002";

export async function sendAgentMessage(
  prompt: string,
  sessionId?: string,
): Promise<AgentChatResponse> {
  const response = await fetch(`${AGENT_BASE_URL}/chat`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      prompt,
      ...(sessionId ? { session_id: sessionId } : {}),
    } satisfies AgentChatRequest),
  });

  const result = await response.json() as
    | AgentChatResponse
    | AgentErrorResponse;

  if (!response.ok) {
    const message = "error" in result
      ? result.error
      : `Agent 请求失败：HTTP ${response.status}`;
    throw new Error(message);
  }

  return result as AgentChatResponse;
}
```

### 5.4 Axios 封装

```typescript
import axios from "axios";

const agentApi = axios.create({
  baseURL: import.meta.env.VITE_AGENT_BASE_URL
    ?? "http://127.0.0.1:8002",
  timeout: 190_000,
});

export async function sendAgentMessage(
  prompt: string,
  sessionId?: string,
): Promise<AgentChatResponse> {
  const response = await agentApi.post<AgentChatResponse>("/chat", {
    prompt,
    ...(sessionId ? { session_id: sessionId } : {}),
  } satisfies AgentChatRequest);

  return response.data;
}
```

请求超时建议略大于后端 SGLang 请求超时。当前后端默认生成超时为 180 秒，因此示例使用 190 秒。

## 6. 图片聊天接入

### 6.1 使用文件上传

```typescript
export async function sendAgentImageMessage(
  prompt: string,
  file: File,
  sessionId?: string,
): Promise<AgentChatResponse> {
  const formData = new FormData();
  formData.append("prompt", prompt);
  formData.append("file", file);

  if (sessionId) {
    formData.append("session_id", sessionId);
  }

  const response = await fetch(`${AGENT_BASE_URL}/chat`, {
    method: "POST",
    body: formData,
  });

  const result = await response.json() as
    | AgentChatResponse
    | AgentErrorResponse;

  if (!response.ok) {
    const message = "error" in result
      ? result.error
      : `图片请求失败：HTTP ${response.status}`;
    throw new Error(message);
  }

  return result as AgentChatResponse;
}
```

使用 `FormData` 时不要手动设置 `Content-Type`。浏览器会自动生成包含 boundary 的正确请求头。

### 6.2 使用 base64 JSON

```typescript
export async function fileToBase64(file: File): Promise<string> {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = () => resolve(String(reader.result));
    reader.onerror = () => reject(reader.error);
    reader.readAsDataURL(file);
  });
}

const image = await fileToBase64(file);

const response = await fetch(`${AGENT_BASE_URL}/chat`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    session_id: currentSessionId,
    prompt: "描述这张图片",
    image,
  } satisfies AgentChatRequest),
});
```

文件上传通常比前端主动构造 base64 JSON 更节省浏览器内存，优先推荐 `FormData`。

## 7. 会话状态管理

### 7.1 单会话页面

只有一个聊天窗口时，可以将 ID 保存到 `localStorage`：

```typescript
const SESSION_STORAGE_KEY = "llm_agent_session_id";

export function getAgentSessionId(): string | undefined {
  return localStorage.getItem(SESSION_STORAGE_KEY) ?? undefined;
}

export function saveAgentSessionId(sessionId: string): void {
  localStorage.setItem(SESSION_STORAGE_KEY, sessionId);
}

export function removeAgentSessionId(): void {
  localStorage.removeItem(SESSION_STORAGE_KEY);
}
```

发送消息后必须保存后端实际返回的 ID：

```typescript
const result = await sendAgentMessage(
  prompt,
  getAgentSessionId(),
);

saveAgentSessionId(result.session_id);
```

### 7.2 多会话页面

多会话系统应为每条会话分别保存 `sessionId`：

```typescript
export interface ChatConversation {
  id: string;
  sessionId: string;
  title: string;
  messages: ChatMessage[];
}
```

如果前端已经有稳定的会话 ID，可以令：

```typescript
conversation.sessionId = conversation.id;
```

发送消息时必须读取当前选中会话，而不是读取一个全局固定 ID：

```typescript
const conversation = conversationsById[currentConversationId];

const result = await sendAgentMessage(
  prompt,
  conversation.sessionId,
);
```

### 7.3 新建会话

```typescript
export function createConversation(): ChatConversation {
  const id = crypto.randomUUID();

  return {
    id,
    sessionId: id,
    title: "新对话",
    messages: [],
  };
}
```

新建会话应使用全新的 ID，不要继续使用上一个会话的 ID。

### 7.4 切换会话

切换时只需切换当前 `conversation`，下一次请求自然会携带该会话自己的 `sessionId`。前端不需要向后端发送专门的“切换会话”请求。

## 8. 清空上下文

清空指定会话的后端记忆：

```typescript
export async function clearAgentMemory(
  sessionId: string,
): Promise<ClearMemoryResponse> {
  const response = await fetch(
    `${AGENT_BASE_URL}/sessions/${encodeURIComponent(sessionId)}/memory`,
    {
      method: "DELETE",
    },
  );

  const result = await response.json() as
    | ClearMemoryResponse
    | AgentErrorResponse;

  if (!response.ok) {
    const message = "error" in result
      ? result.error
      : `清空会话失败：HTTP ${response.status}`;
    throw new Error(message);
  }

  return result as ClearMemoryResponse;
}
```

调用：

```typescript
await clearAgentMemory(currentConversation.sessionId);
```

返回示例：

```json
{
  "status": "ok",
  "session_id": "browser-001",
  "cleared": true
}
```

`cleared=false` 表示后端中不存在该会话，接口本身仍然执行成功。

“清空上下文”和“新建会话”语义不同：

- 清空上下文：保留原 `session_id`，删除该 ID 对应的历史。
- 新建会话：生成全新的 `session_id`，原会话仍可继续使用。

## 9. 推荐的前端发送流程

```typescript
async function handleSendMessage(prompt: string, file?: File) {
  const conversation = getCurrentConversation();
  if (!conversation || !prompt.trim()) {
    return;
  }

  appendLocalUserMessage(conversation.id, {
    content: prompt,
    file,
  });
  setConversationLoading(conversation.id, true);

  try {
    const result = file
      ? await sendAgentImageMessage(
          prompt,
          file,
          conversation.sessionId,
        )
      : await sendAgentMessage(
          prompt,
          conversation.sessionId,
        );

    updateConversationSessionId(
      conversation.id,
      result.session_id,
    );
    appendLocalAssistantMessage(conversation.id, result);
  } catch (error) {
    appendLocalErrorMessage(
      conversation.id,
      error instanceof Error ? error.message : "请求失败",
    );
  } finally {
    setConversationLoading(conversation.id, false);
  }
}
```

前端本地消息列表和后端记忆是两套不同数据：

- 前端消息列表负责页面展示、刷新恢复和用户交互。
- 后端记忆负责将上下文传给大模型。

前端仍应正常保存消息列表，不能仅依赖后端内存。

## 10. 错误处理

### 10.1 常见状态码

| 状态码 | 含义 | 前端处理建议 |
|---|---|---|
| `200` | 请求成功 | 渲染响应并保存 `session_id` |
| `400` | 缺少 prompt 或 `session_id` 非法 | 展示参数错误，不重试 |
| `500` | Agent 业务处理异常 | 展示失败消息，可允许用户手动重试 |
| `503` | `/ready` 检测到数据库或 SGLang 不可用 | 展示服务暂不可用，稍后重试 |

### 10.2 超时

多模态模型生成可能耗时较长，前端建议：

- 请求超时设置为 190 秒或更长。
- 请求期间禁用当前会话的重复发送按钮。
- 显示明确的生成中状态。
- 不要因为页面组件重新渲染重复提交同一个请求。
- 支持使用 `AbortController` 主动取消前端等待。

### 10.3 重试注意事项

当前 `/chat` 没有请求幂等键。自动重试可能让同一条用户消息被后端记忆两次，因此不建议对 `POST /chat` 做无提示的无限自动重试。

推荐只允许用户点击“重新发送”，并在重试前确认上一请求确实失败。

## 11. 健康检查

页面加载或运维监控可以调用：

```typescript
export async function checkAgentReady(): Promise<boolean> {
  try {
    const response = await fetch(`${AGENT_BASE_URL}/ready`);
    return response.ok;
  } catch {
    return false;
  }
}
```

`/health` 只说明 Flask 进程存在；真正发送聊天请求前，更有意义的是 `/ready`：

```json
{
  "status": "ok",
  "database": "ok",
  "llm": "ok",
  "llm_model": "internvl3.5-8b"
}
```

## 12. 环境变量

Vite 项目可以增加：

```dotenv
VITE_AGENT_BASE_URL=http://192.168.96.201:8002
```

读取：

```typescript
const AGENT_BASE_URL = import.meta.env.VITE_AGENT_BASE_URL;
```

不要将 SGLang 的 `LLM_API_KEY` 配置到浏览器。前端只访问 `llm_agent_service:8002`，由 Agent 后端访问 SGLang。否则 SGLang API Key 会暴露在浏览器代码和网络请求中。

推荐网络结构：

```text
浏览器
  -> llm_agent_service:8002
       -> SGLang:8000
       -> PostgreSQL
```

## 13. 当前限制

当前会话记忆使用 Agent 进程内存：

- Agent 服务重启后历史丢失。
- 多个 Agent 进程之间不共享历史。
- 多台 Agent 服务器之间不共享历史。
- 最多保存的会话和消息数量由后端配置限制。
- 历史图片不会保存，只保留图片提示文字和模型生成的描述。

因此，前端刷新页面时可以通过保存 `session_id` 继续会话，但 Agent 服务重启后，即使继续使用原 ID，模型也无法恢复重启前的上下文。

生产环境后续可以将后端记忆替换为 Redis、PostgreSQL 或 LangGraph checkpointer；前端 `session_id` 协议可以保持不变。

## 14. 联调步骤

### 14.1 检查服务

```bash
curl http://<AGENT_HOST>:8002/health
curl http://<AGENT_HOST>:8002/ready
```

### 14.2 验证文本记忆

```bash
curl -X POST http://<AGENT_HOST>:8002/chat \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "frontend-test-001",
    "prompt": "请记住，我的测试编号是9527"
  }'
```

```bash
curl -X POST http://<AGENT_HOST>:8002/chat \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "frontend-test-001",
    "prompt": "我的测试编号是什么？"
  }'
```

预期第二轮能够回答 `9527`。

### 14.3 验证会话隔离

使用另一个 ID：

```bash
curl -X POST http://<AGENT_HOST>:8002/chat \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "frontend-test-002",
    "prompt": "我的测试编号是什么？"
  }'
```

预期新会话不知道 `frontend-test-001` 中的编号。

### 14.4 验证清空

```bash
curl -X DELETE \
  http://<AGENT_HOST>:8002/sessions/frontend-test-001/memory
```

再次询问编号，预期模型无法从后端历史中恢复 `9527`。

## 15. 前端验收清单

- [ ] 文本请求包含当前会话的 `session_id`。
- [ ] 图片 `FormData` 请求包含当前会话的 `session_id`。
- [ ] 前端保存后端响应中的 `session_id`。
- [ ] 同一会话后续请求复用同一个 ID。
- [ ] 新建会话生成新的 ID。
- [ ] 切换会话时切换到对应的 ID。
- [ ] 不同用户不会共用固定的 `default` ID。
- [ ] 清空上下文按钮调用 DELETE 接口。
- [ ] 前端自身仍保存用于展示的消息列表。
- [ ] 请求中展示加载状态并防止重复提交。
- [ ] 对 `400/500/503` 和网络超时有明确提示。
- [ ] 浏览器代码中没有暴露 SGLang API Key。
- [ ] 完成同会话记忆、不同会话隔离和清空记忆联调。
