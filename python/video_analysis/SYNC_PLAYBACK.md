# 同帧同步模块说明

当前默认使用独立的 WebRTC 实时视频与异步检测框。算法变慢、断开或重载只影响
检测框，不遮挡或暂停原始视频；实时模式只订阅检测 JSON，不请求 JPEG。
检测框按推理输入时间计算，超过一秒或服务给出的有效期限就隐藏，断开及会话变化
立即清理。该模式不承诺两个独立接收链路之间的严格时间对齐，也不外推旧框位置。

界面可以显式切换“同帧验收”，此时后端发送本次推理输入的无框 JPEG 和对应检测
数据，浏览器一起呈现。该模式的画面更新率受推理吞吐限制，用于检查图框对应关系。
两个模式都由浏览器绘制实线检测框，不在图像上画框，也不显示 PRED 标签。

## 文件职责

| 文件 | 主要职责 |
| --- | --- |
| `python/video_analysis/config.py` | 检测服务与同步图像的配置 |
| `python/video_analysis/sync_frame.py` | 将实际推理输入编码为无框 JPEG |
| `python/video_analysis/analyzer.py` | 调度推理、绑定输入帧与结果、向订阅者发布 |
| `python/video_analysis/app.py` | WebSocket 订阅及发送，兼容只收 JSON 的客户端 |
| `lanhu/src/config/syncPlayback.js` | 同步协议边界与浏览器等待参数 |
| `lanhu/src/utils/detectionProtocol.js` | 消息与图像帧编号校验 |
| `lanhu/src/utils/exactVideoRenderer.js` | 同步图像解码、连续呈现、帧序保护及资源释放 |
| `lanhu/src/utils/alignedVideoRenderer.js` | 实时视频上的异步框绘制与过期清理，不覆盖原始视频 |
| `lanhu/src/components/VideoWithOverlay/index.jsx` | 连接播放器、检测订阅与呈现模块，展示状态 |

已有的近似时间对齐模块保留原有职责；同帧模式不使用它来猜测框对应的画面。

## 配置与端口

管理员在仓库根目录的 `local-ports.env` 分配个人端口，该文件保持 Git 忽略，
仅由本地启动脚本读取；应用源码及 Vite 配置不直接读取它。
前端保留主分支默认端口 3000，由启动脚本使用 `--port` 指定个人端口。
后端通过 `VITE_BACKEND_ORIGIN` 注入。默认共享模式的 `/ws/detections` 连接
`VIDEO_ANALYSIS_SHARED_ORIGIN`（默认 `http://127.0.0.1:28010`）；同源
`/shared-media/live/camera_N/` 连接 `SHARED_MEDIA_ORIGIN`（默认
`http://127.0.0.1:18889`）。WHEP 会话 Location、DELETE 同样经过媒体代理。
设置 `VITE_VIDEO_ANALYSIS_MODE=local` 才恢复 `VITE_VIDEO_ANALYSIS_ORIGIN` 和
`VITE_MEDIA_PORT` 的独立实验配置，避免旧启动器把默认共享前端连回本地模型。
直接执行 `npm run dev` 使用共享默认配置；个人工作区按现有启动脚本运行。
WebSocket 沿用 `/ws/detections`，通过前端代理连接检测服务，不增加监听端口。

同步播放通过 `?frames=1` 订阅。同一服务的所有同步订阅者共享现有推理任务。
普通订阅者继续接收不含图像的检测 JSON。

| 配置 | 当前值 | 所在文件 |
| --- | --- | --- |
| `VIDEO_ANALYSIS_SYNC_FPS` | 默认 8，上限 60 | 后端 `config.py`，可由环境变量覆盖 |
| `SYNC_FRAME_WIDTH` / `SYNC_FRAME_HEIGHT` | 1280 / 720 | 后端编码配置、前端协议边界 |
| `SYNC_JPEG_QUALITY` | 80 | 后端 `config.py` |
| `SYNC_MAX_JPEG_BYTES` | 2 MiB | 后端 `config.py` |
| `SYNC_MAX_BASE64_LENGTH` | 2796204 | 前端 `syncPlayback.js` |
| `SYNC_STALL_MS` | 500 毫秒无新同步帧时标记暂停，保留当前画面及其检测框 | 前端 `syncPlayback.js` |
| `REALTIME_MAX_RESULT_AGE_MS` | 1000 毫秒，实时框从推理输入时间起的最大年龄 | 前端 `syncPlayback.js` |

修改协议尺寸或字节上限时，需要同时核对前后端边界。

## 同步约束

图像取自本次 `worker.infer()` 使用的输入，推理完成后不重新读取最新帧来配图。
图像与检测结果处于同一消息内，使用同一个 `frame_id` 和外层摄像头、会话、epoch 标识。
浏览器解码完成后只使用该消息中的框，在同一次动画回调中更新图像层和检测框层。
新消息不会替换仍在解码的旧图像所关联的检测数据。

每路浏览器只保留一个已解码画面及一个正在解码的画面，不保留 JPEG 历史队列。
借鉴 ActiveVAU `frontend/src/components/VideoWithOverlay.tsx` 的绘制逻辑：短暂
抖动、暂无新帧时保留最后绘制的画面，避免正常抖动变成可见黑闪。超过暂停阈值、
结果过期或当前结果被清空时，保留最后的同步图像及该帧的检测框快照，并显示等待新帧。
新图像解码完成后一起替换图像与检测框；零目标结果随其对应图像呈现时清框。
过期结果不能用于呈现新帧；检测框开关仍可隐藏、恢复当前画面的标注。
同帧模式始终由同步画布呈现，不因检测间隔自动露出另一条 WebRTC 时间轴；
用户可显式切回默认实时视频。会话或 epoch 切换、页面隐藏和组件卸载时释放图像，
新会话首帧就绪前显示等待状态。同一会话中重复或倒退的帧不能覆盖已显示帧。

ActiveVAU 的 WebRTC 缓存与检测时间匹配仍是近似对齐。本模块保留现有同消息
图像和检测框绑定，借鉴其抖动保留画面及资源清理方式。

`VIDEO_ANALYSIS_SYNC_FPS=8` 只参与旧检测链路的同步调度，不限制或提高 BoT-SORT
吞吐。BoT-SORT 由推理间隔、模型容量和摄像头轮询决定速率；四路共享单模型
时串行处理，不保证每秒呈现 8 帧，也不处理摄像头的每一帧。
负载过高时丢弃整组画面及结果，保持已呈现画面的框与图像一致。
实际帧率、延迟和原始实时模式是否可用仍取决于推理、网络及浏览器编解码器。
