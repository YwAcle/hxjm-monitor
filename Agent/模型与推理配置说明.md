# 模型与推理配置说明

本文说明 `Agent/` 下两个服务共用的模型配置、推理引擎启动、API 切换与日志约定。涉及的文件只有三类：`.env`（本地实际配置，不入库）、`.env.example`（模板）、`scripts/`（启动与配置解析）。业务接口与数据依赖分别见 `llm_agent_service/功能说明.md` 和 `llm_report_service/功能说明.md`。

`llm_agent_service`（对话 Agent）与 `llm_report_service`（报告 Worker）**共用同一份模型配置**：两者都通过 `llm_report_service/llm/settings.py` 解析，Shell 启动脚本也复用同一个解析器。改一处，两边同时生效。

## 1. 配置加载链路

Shell 启动脚本（`scripts/start_*.sh`）的顺序：

1. 处理位置参数，例如 `start_all.sh api` 会先导出 `LLM_MODE=api`，`start_all.sh vllm` 会导出 `LLM_MODE=local LLM_BACKEND=vllm`；
2. `load_env_defaults` 读取 `Agent/.env`，**只填充进程环境中尚不存在的变量**，因此已经导出的环境变量优先；
3. 调用 `scripts/resolve_model_config.py --shell`，由 Python 的 `resolve_model_settings` 归一化配置，再把结果导出回 Shell；
4. 各启动脚本使用归一化后的 `LLM_*` 值拼装命令行参数。

Python 服务直接启动时，`settings.py` 在导入阶段读取 `.env`（`override=False`），再执行同一套归一化并把结果写回 `os.environ`。

优先级从高到低：

```
命令行参数 > 进程环境变量 > Agent/.env > 代码默认值
```

`start_all.sh` 的位置参数（`api` / `local` / `vllm` / `sglang`）优先于 `.env` 里的 `LLM_MODE` 和 `LLM_BACKEND`。

`./scripts/start_all.sh ... --show-config` 只打印归一化结果，不启动服务，并隐藏所有以 `_API_KEY` 结尾的值。

## 2. 两种运行模式

`LLM_MODE` 是持久开关，修改后需重启服务：

| 模式 | 行为 | 需要的资源 |
| --- | --- | --- |
| `local` | 启动或复用本地 vLLM / SGLang 接口 | 模型权重、GPU、对应 Python 环境 |
| `api` | 只连接 `LLM_REMOTE_*` 指向的远端接口 | 可访问的网络与密钥，不需要本地权重 |

API 只支持 **OpenAI Chat Completions 兼容协议**（Bearer 鉴权），不是厂商任意原生接口。图片/视频报告要求对方模型支持 `image_url` 多模态输入。

## 3. API 模式

最小配置：

```dotenv
LLM_MODE=api
LLM_REMOTE_BASE_URL=https://provider.example/v1
LLM_REMOTE_MODEL_ID=your-model-id
LLM_REMOTE_API_KEY=your-api-key
LLM_REMOTE_ENABLE_THINKING=
LLM_REMOTE_RESPONSE_FORMAT=json_object
LLM_HEALTHCHECK=auto
```

规则：

- `LLM_REMOTE_BASE_URL` 是接口根地址，客户端自动追加 `/chat/completions`；**不要**填写完整端点。
- 必须是 `http` / `https` 地址，不能内嵌用户名、密码、查询参数或片段，也不能以 `/chat/completions`、`/responses` 结尾；密钥只能放在 `LLM_REMOTE_API_KEY`。
- `BASE_URL` 与 `MODEL_ID` 缺失会立即报错。API 模式**不会**回退到本地地址、模型名或密钥。
- `LLM_REMOTE_ENABLE_THINKING` 留空时不下发 `chat_template_kwargs`，由服务端默认决定（多数服务商默认开启思考）；只有服务商明确支持时才设为 `true` / `false`。本地 `LLM_ENABLE_THINKING` 不影响 API 模式。
- `LLM_REMOTE_RESPONSE_FORMAT` 控制结构化输出：
  - `json_schema`：透传调用方的完整 JSON Schema；
  - `json_object`：降级为普通 JSON 模式；
  - `none`：不发送 `response_format`，只靠提示词和程序侧校验；
  - 未设置时解析器默认 `json_schema`（`.env.example` 显式给了 `json_object`）。只影响原本就带格式要求的请求，普通聊天不会额外添加。
- `LLM_HEALTHCHECK=auto` 时 API 模式跳过 `/models`，以适配不提供模型列表的服务商；`models` 强制检查，`none` 完全跳过。
- **API 模式绝不启动本地模型**，即使地址是 localhost 或 `START_VLLM=1` / `START_SGLANG=1`。
- 使用第三方 API 会把文本与图片发送给服务商，需自行确认数据合规与计费。

临时切换而不改 `.env`：

```bash
./scripts/start_all.sh api
LLM_MODE=api ./scripts/start_agent.sh
LLM_MODE=api ./scripts/start_report.sh
```

## 4. 本地模式公共配置

```dotenv
LLM_MODE=local
LLM_BACKEND=vllm
LLM_MODEL_PATH=./Qwen3.8-27B-AWQ-INT4
LLM_MODEL_ID=Qwen/Qwen3.8-27B-AWQ-INT4
LLM_SERVER_HOST=0.0.0.0
LLM_SERVER_PORT=8000
LLM_API_KEY=unused

CUDA_VISIBLE_DEVICES=2,3
LLM_TP_SIZE=2
LLM_CONTEXT_LENGTH=65536
LLM_GPU_MEMORY_UTILIZATION=0.85
LLM_DTYPE=bfloat16
LLM_ENABLE_THINKING=false
LLM_CHAT_TEMPLATE=./scripts/chat_templates/qwen3_5_no_thinking.jinja
```

| 配置 | 用途 |
| --- | --- |
| `LLM_BACKEND` | `vllm` 或 `sglang`；决定客户端类型和启动脚本 |
| `LLM_MODEL_PATH` | 模型目录或模型 ID；以 `.` 开头的相对路径按 `Agent/` 解析 |
| `LLM_MODEL_ID` | 客户端请求名，同时作为本地服务的 `served-model-name`；省略时取模型目录名 |
| `LLM_SERVER_HOST` / `LLM_SERVER_PORT` | 模型服务监听地址和端口 |
| `LLM_BASE_URL` | 客户端地址；未设置时按端口生成 `http://127.0.0.1:<port>/v1` |
| `CUDA_VISIBLE_DEVICES` / `LLM_TP_SIZE` | 可见 GPU 与张量并行数 |
| `LLM_CONTEXT_LENGTH` | vLLM 的 `max-model-len` / SGLang 的 `context-length` |
| `LLM_GPU_MEMORY_UTILIZATION` | vLLM 的 `gpu-memory-utilization` / SGLang 的 `mem-fraction-static`；两者语义不同，切换后仍需按显存调整 |
| `LLM_DTYPE` / `LLM_CHAT_TEMPLATE` | 数据类型与聊天模板；未指定模板时使用模型目录下的 `chat_template.jinja` |

注意：

- **更换模型时必须同步修改或删除 `LLM_MODEL_ID`**，否则客户端继续请求旧名称，启动检查会直接报模型名不匹配。
- 模板文件在仓库内为 `scripts/chat_templates/qwen3_5_no_thinking.jinja`，面向 Qwen3.5 架构并保留多模态占位符；换模型时需一并核对模板适配。
- 当前上下文长度按最近运行的 AWQ 服务配置，未做满长度或并发压力测试。

## 5. 两个本地引擎

### 5.1 vLLM

```dotenv
VLLM_ENV_ROOT=./.venv-vllm-qwen
# 可选，优先级高于 ENV_ROOT
VLLM_PYTHON_BIN=/path/to/venv/bin/python

VLLM_MAX_NUM_SEQS=2
VLLM_LIMIT_MM_PER_PROMPT='{"image":4,"video":0}'
VLLM_ATTENTION_BACKEND=TRITON_ATTN
VLLM_MAX_NUM_BATCHED_TOKENS=8192
VLLM_NO_USAGE_STATS=1
```

`start_vllm.sh` 会：

- 强制 `LLM_MODE=local LLM_BACKEND=vllm`；
- 检查解释器可执行、能 `import vllm`、CUDA 可初始化；
- 组装 `vllm.entrypoints.openai.api_server`：模型、`served-model-name`、host/port、dtype、`max-model-len`、`gpu-memory-utilization`、`tensor-parallel-size`、`max-num-seqs`（未设置时 8）、`limit-mm-per-prompt`（未设置时 `{"image":32}`）、`api-key`、`trust-remote-code`、聊天模板；
- 可选追加 `--max-num-batched-tokens`、`--attention-backend`、`--reasoning-parser`、`--default-chat-template-kwargs`、`--enforce-eager`；
- 当未显式设置 `VLLM_DEFAULT_CHAT_TEMPLATE_KWARGS` 时，用 `LLM_ENABLE_THINKING` 生成 `{"enable_thinking": false}` 或 `true`；
- 缓存写入 `.runtime-cache/vllm/{huggingface,triton,torch}`；
- 其余参数通过 `"$@"` 原样传给 vLLM，例如 `./scripts/start_vllm.sh --enforce-eager`。

图片上限覆盖报告抽帧和 Agent 截图；调整帧数时需同步考虑该上限与显存。

### 5.2 SGLang

```dotenv
SGLANG_ENV_ROOT=/path/to/sglang-env
# 可选
SGLANG_BIN=/path/to/sglang
SGLANG_PYTHON_BIN=/path/to/python
CUDA_TOOLKIT=/usr/local/cuda-12.2
```

`start_sglang.sh` 会：

- 强制 `LLM_MODE=local LLM_BACKEND=sglang`；
- 校验 `sglang`、Python、`x86_64-conda-linux-gnu-gcc/g++`、`nvcc` 均存在且可执行，模型目录下 `config.json` 可读；
- 设置 `CUDA_HOME`、`CC`/`CXX`、`PYTORCH_NVCC` 等编译变量，缓存写入 `.runtime-cache/{huggingface,triton-cuda122-gcc11,torch-cuda122-gcc11,tvm-ffi-cuda122-gcc11,flashinfer-cuda122-gcc11}`；
- 通过 `launch_sglang.py` 启动：`--model-path`、`--tokenizer-path`、`--served-model-name`、host/port、`--api-key`、`--dtype`、`--context-length`、`--mem-fraction-static`、`--tp-size`、`--enable-multimodal`、`--attention-backend triton`、`--sampling-backend pytorch`、`--mm-attention-backend triton_attn`、`--trust-remote-code`、聊天模板；
- 启动前 `unset SGLANG_PORT`，避免内部变量占用 HTTP 端口；
- 不读取任何 `VLLM_*` 参数，也不额外传递思考开关，思考行为由模板决定。

两个引擎共用同一个端口，**不能同时启动**。

### 5.3 旧字段回退

公共字段未设置时，解析器会读取旧的后端专属字段：

| 公共字段 | 回退字段 | 默认值 |
| --- | --- | --- |
| `LLM_TP_SIZE` | `VLLM_TP_SIZE` / `SGLANG_TP_SIZE` | `1` |
| `LLM_CONTEXT_LENGTH` | `VLLM_MAX_MODEL_LEN` / `SGLANG_CONTEXT_LENGTH` | `14588` |
| `LLM_GPU_MEMORY_UTILIZATION` | `VLLM_GPU_MEMORY_UTILIZATION` / `SGLANG_MEM_FRACTION_STATIC` | `0.80` |
| `LLM_CHAT_TEMPLATE` | `VLLM_CHAT_TEMPLATE` / `SGLANG_CHAT_TEMPLATE` | 空 |
| `LLM_DTYPE` | `VLLM_DTYPE` / `SGLANG_DTYPE` | `bfloat16` |

`LLM_MODEL_PATH` 也可回退到 `VLLM_MODEL_PATH` / `SGLANG_MODEL_PATH`；`LLM_SERVER_PORT` 回退到 `VLLM_PORT` / `SGLANG_PORT`。公共字段与新配置优先，无需同时维护两套。

## 6. 启动与切换

在 `Agent/` 目录执行：

| 命令 | 启动内容 |
| --- | --- |
| `./scripts/start_all.sh` | 按 `.env` 的 `LLM_MODE` / `LLM_BACKEND` 启动模型（或连接 API）、报告 Worker、Agent |
| `./scripts/start_all.sh vllm` | 强制本地 vLLM + 两个业务服务 |
| `./scripts/start_all.sh sglang` | 强制本地 SGLang + 两个业务服务 |
| `./scripts/start_all.sh api` | 只连接远端 API + 两个业务服务 |
| `./scripts/start_all.sh [模式] --show-config` | 只打印归一化配置 |
| `./scripts/start_vllm.sh` | 只启动 vLLM |
| `./scripts/start_sglang.sh` | 只启动 SGLang |
| `./scripts/start_agent.sh` | 等待模型接口后启动 Agent |
| `./scripts/start_report.sh` | 等待模型接口后启动报告 Worker |

`start_all.sh` 的行为：

1. 先做模型接口检查；已就绪且模型名匹配则复用，不启动新进程；
2. 不可用时按 `START_VLLM` / `START_SGLANG` 决定：`auto` 只在本地地址时启动，`1` 强制启动，`0` 不启动；
3. API 模式强制 `START_MODEL=0`；
4. 模型启动后等待 `/models`（跳过检查时直接通过），再启动报告 Worker 和 Agent；
5. 等待 Agent `/ready`，默认 360 秒超时；
6. Ctrl+C 只停止本脚本启动的进程；复用的外部模型需在原入口停止。

**切换推理引擎时先停旧服务再启新服务**，否则新引擎会因端口占用启动失败。

根目录的 `start_services_vllm.sh`、`start_services_sglang.sh` 以及两个服务目录下的旧启动脚本，都转发到 `scripts/`，行为一致。

## 7. 健康检查语义

`check_model_endpoint.py` 与客户端 `check_health()` 使用同一策略：

| `LLM_HEALTHCHECK` | 本地模式 | API 模式 |
| --- | --- | --- |
| `auto` | 请求 `/models` 并校验模型名 | 跳过 |
| `models` | 请求 `/models` | 请求 `/models` |
| `none` | 跳过 | 跳过 |

返回码：

- `0`：就绪，或已按策略跳过；
- `1`：接口不可达、返回异常或数据结构不合法；
- `2`：接口可用但模型列表中没有 `LLM_MODEL_ID`。启动脚本收到 `2` 会立即退出，避免服务起来后聊天才 404。

**跳过检查不等于连通性或鉴权验证**，Agent 的 `/ready` 也不保证远端真实可用；网络、权限、额度和费用只能通过实际请求确认。所有探针都不会发送可能计费的聊天请求。

## 8. 客户端、超时与日志

```dotenv
LLM_CONNECT_TIMEOUT_S=5
LLM_REQUEST_TIMEOUT_S=180
LLM_MAX_RETRIES=2

AGENT_REQUEST_TIMEOUT_S=180
AGENT_ANSWER_MAX_NEW_TOKENS=2048
```

| 配置 | 作用 |
| --- | --- |
| `LLM_CONNECT_TIMEOUT_S` / `LLM_REQUEST_TIMEOUT_S` | 连接与单次请求超时，两个服务共用 |
| `LLM_MAX_RETRIES` | `429/502/503/504` 与传输错误的重试次数，退避 `min(0.5×2^n, 2s)`；其他 4xx/5xx 立即失败 |
| `LLM_MAX_NEW_TOKENS` | 启动脚本的默认生成长度：Agent 决策 512，报告 1024 |
| `AGENT_REQUEST_TIMEOUT_S` | Agent 整次请求总超时，需大于模型调用耗时 |
| `AGENT_ANSWER_MAX_NEW_TOKENS` | Agent 最终正文长度上限，需与超时匹配 |

日志：

```dotenv
LOG_WRITE_MODE=overwrite
# 可选，按服务覆盖
# MODEL_LOG_WRITE_MODE=append
# AGENT_LOG_WRITE_MODE=append
# REPORT_LOG_WRITE_MODE=append
```

| 文件 | 路径 |
| --- | --- |
| 模型引擎日志 | `.runtime-cache/llm-report-service/{vllm,sglang}.log` |
| 报告 Worker | `.runtime-cache/service-stack/<label>/report.log` |
| Agent | `.runtime-cache/service-stack/<label>/agent.log` |
| Agent 事件 | `.runtime-cache/service-stack/<label>/agent.jsonl` |

`<label>` 是后端名（`vllm` / `sglang`），API 模式为 `api`。可用 `SERVICE_STACK_RUNTIME_DIR` 重定向整个目录，或用 `AGENT_STACK_LOG` / `REPORT_STACK_LOG` / `VLLM_LOG` / `SGLANG_LOG` 单独指定。`overwrite` 在启动时清空文件，`append` 保留历史。

本地请求建议设置：

```dotenv
NO_PROXY=127.0.0.1,localhost
```

若环境中已有 `NO_PROXY`，在其原值后追加，不要覆盖。

## 9. 已知边界

- **不自动安装依赖**：`VLLM_ENV_ROOT` / `SGLANG_ENV_ROOT` 必须预先存在并安装好对应引擎；SGLang 还依赖固定路径的 CUDA Toolkit 与 conda 编译器。仓库中原有的 `requirements-vllm-*.txt` 已移除，环境依赖由各自的 venv/conda 环境提供。
- **模型与模板强耦合**：当前模板服务于 Qwen3.5 架构的 Qwen3.8 模型。vLLM 0.17.1 下不要只设 `LLM_ENABLE_THINKING=false` 又启用 `qwen3` reasoning parser，否则正文可能被归入推理字段。
- **模型名必须一致**：`LLM_MODEL_PATH` 与 `LLM_MODEL_ID` 不一致时，`/models` 校验会以返回码 `2` 终止启动。
- **本地模式连接远端地址**：`auto` 不会自动启动本地模型，但仍会要求远端的 `/models` 与 `/chat/completions`；不提供模型列表时需设 `LLM_HEALTHCHECK=none`。
- **API 模式无回退**：远程配置不完整会直接报错，不会静默使用本地服务。
- **端口唯一**：两个引擎共用 `LLM_SERVER_PORT`，同一时间只能运行一个。
- **日志默认覆盖**：`LOG_WRITE_MODE=overwrite` 会清空旧日志；需要保留历史时改为 `append`。

## 10. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 启动即报模型名不匹配 | `/models` 返回的名称与 `LLM_MODEL_ID` 不一致；检查模型路径、`served-model-name` 和 `.env` |
| 端口已被占用 | 旧模型进程未停止，或另一用户占用了 `LLM_SERVER_PORT` |
| API 模式报地址无效 | `LLM_REMOTE_BASE_URL` 带了 `/chat/completions`、查询参数或内嵌凭据 |
| 请求很慢 | API 模式思考默认开启；显式设置 `LLM_REMOTE_ENABLE_THINKING=false` |
| 服务启动成功但聊天 404 | 健康检查被跳过（`none` 或 API 的 `auto`），实际模型名或路由不对 |
| 报告/Agent 日志为空 | 检查 `LOG_WRITE_MODE` 与 `<label>` 目录，确认启动的是哪个模式 |
