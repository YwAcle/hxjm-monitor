# llm_agent_service 功能说明

本文说明对话式监控助手服务（`Agent/llm_agent_service`）的定位、处理流程、工具能力、接口与配置，供接手开发和联调时查阅。接口字段的前端侧细节见 `开发文档/` 下的对接文档，实现细节见同目录 `README.md`。

## 1. 服务定位

`llm_agent_service` 是监控大屏的对话后端。前端把用户的一句话（可附带一张图片）连同 `session_id` 发给服务，服务让大模型在**一组只读工具**上做决策：

- 查询数据库中已有的监控轨迹、大模型监控报告、异常事件记录；
- 按完整姓名定位已登记人员；
- 调用远端 CLIP-ReID / Chinese-CLIP 特征服务，在已入库的行人身份库中做相似度检索；
- 对用户上传的图片做行人检测、裁剪、超分。

最后用自然语言回答，并通过 SSE 把答案流式推回前端。

服务**只读业务库**：不写轨迹、报告、异常表，不触发摄像头、不做实时推理、不生成新的监控报告。报告生成由 `llm_report_service` 独立完成。

## 4. 请求处理流程

```
POST /chat 或 /chat/stream
  → app.py：大小、prompt 长度、session_id、trace_id、图片格式与尺寸校验
  → 图片归一化为 Data URL；必要时登记为会话图片资产
  → AgentService.process / stream
      → 多人截图待选择时：尝试按“选择2”“第二个人”“取消”恢复
      → AgentExecutor.run
          → 决策循环（最多 3 步）
              每次调用模型，要求返回严格 JSON：
                {"action":"tool","tool":"…","arguments":{…}}
                {"action":"final","answer":"…"}
              工具结果回填为一条 HumanMessage 继续下一轮
          → 得到 final 后结束循环
      → 流式接口再发起一次模型调用，逐 token 输出正文
  → SSE 逐条下发 status / delta / result / done / error
```

### 4.1 决策循环

- 系统提示词 + 11 个工具描述 + 会话历史 + 用户消息（+ 图片）一起送入模型。
- 决策输出受 JSON Schema 约束（`AgentAction` 的 `tool`/`final` 联合结构）。API 模式可因 `LLM_REMOTE_RESPONSE_FORMAT` 降级为 `json_object` 或无约束。
- 最多 `max_steps=3` 步；用完仍未给出 final 时返回「未能在限定步骤内完成查询。」，`finish_reason=max_steps`。
- 总耗时超过 `AGENT_REQUEST_TIMEOUT_S`（默认 180 秒）返回「查询超时，请稍后重试。」，`finish_reason=timeout`。
- 模型返回的动作无法解析时重试一次；仍失败则返回「暂时无法解析模型动作。」。
- 同一次请求中，工具名 + 参数完全相同的重复调用会被拦截并终止，`finish_reason=error`，避免模型死循环。
- 工具返回内容超过 `max_tool_result_chars=12000` 字符时截断后再回填。
- 工具执行失败不会中断请求：错误结果作为 observation 交回模型，由模型决定继续或如实说明。

### 4.2 两种回答路径

| 路径 | 模型调用次数 | 说明 |
| --- | --- | --- |
| `POST /chat`（非流式） | 每步一次 | 最后一次决策调用同时产出正文，`max_new_tokens=AGENT_ANSWER_MAX_NEW_TOKENS` |
| `POST /chat/stream`（SSE） | 每步一次 + 最后一次流式调用 | 决策阶段传 `prepare_stream=True`，强制 final 的 `answer` 为「准备回答」；决策结束后用更完整的上下文再调用一次模型，逐 token 输出 |

因此流式链路首字延迟 = 一次完整决策调用 + 流式调用首 token 时间；工具越多、步骤越多，首字越晚。

### 4.3 多轮与恢复

- 同一 `session_id` 保存最近 20 条消息（默认最多 1000 个会话）。
- 上传的图片按会话保存，供后续「这张图」「放大它」等追问复用。
- 截图检测到多人时，服务暂存原图与候选框，回答里列出编号；用户回复「选择2」「第二个人」「2号」等即恢复检索，回复「取消」清除。未选择时默认 300 秒后过期。

## 5. 工具清单

`build_default_registry` 注册 12 个只读工具（`GET /tools` 可查看实时描述）：

| 工具 | 作用 | 主要参数 |
| --- | --- | --- |
| `parse_time` | 解析「明天下午3点」「最近三天」等时间表达 | `text`, `reference_time?`, `timezone?` |
| `find_person` | 按完整姓名匹配已登记人员 | `query` |
| `query_person_tracklets` | 指定人员 + 时间范围 → 轨迹出现记录（时间、摄像头） | `query`, `time_prompt=今天`, `limit=20` |
| `query_person_reports` | 指定人员 + 时间范围 → 关联的历史报告 | `query`, `time_prompt=今天`, `limit=20` |
| `query_reports_by_time` | 时间范围内全部报告（不需要姓名） | `time_prompt=今天`, `limit=20` |
| `query_vad_events` | 已记录的异常事件；`mode=range\|latest` | `time_prompt=今天`, `limit=20`, `mode=range` |
| `list_known_persons` | 服务缓存的登记人员名单 | 无 |
| `super_resolve_image` | 上传图片 2 倍 / 4 倍插值放大 | `image_base64`（服务端注入）, `prompt` |
| `search_pedestrians_in_screenshot` | 监控截图找人：单人直接检索，多人返回候选框 | `image_base64`, `top_k=5` |
| `search_pedestrians_by_image` | 单人裁剪图 → CLIP-ReID 身份检索 | `image_base64`, `top_k=5` |
| `search_pedestrians_by_description` | 外观文字 → Chinese-CLIP 登记照片检索 | `description`, `top_k=5` |
| `search_pedestrians_by_description_in_history` | 外观文字 → Chinese-CLIP 全部历史轨迹裁剪图检索 | `description`, `top_k=5` |

约定：

- `image_base64` 由执行器从当前请求注入，提示词要求模型不要生成或复制 Base64。
- `top_k` 范围 1～10，默认 5；记录类 `limit` 范围 1～100，默认 20，且都是「本次返回条数」，不是全量统计。
- 四个 `search_pedestrians_*` 工具仅当 `gallery_search` 可用时注册；当前 `app.py` 始终构造它。
- 所有工具声明为 `read_only`，不接受写库操作。

## 6. 行人检索能力

### 6.1 数据模型

检索基于样本管线写入的新轨迹身份体系：

| 表 | 用途 |
| --- | --- |
| `feature_space` | 特征空间定义，检索前校验启用状态、度量方式、维度 |
| `feature` | 行人图片特征向量 |
| `identity` | 身份（`temporary` 临时 / `registered` 登记），含 `display_no`、姓名、工号 |
| `identity_link` | 临时身份与登记身份的关联 |
| `track_identity_assignment` | 轨迹片段到身份的归属 |
| `tracklet` | 轨迹片段（开始时间、摄像头、流 ID） |
| `sample` / `media_asset` | 样本与媒体素材，预览图取自 `media_asset.storage_key` |
| `camera` | 摄像头名称 |

### 6.2 三种入口

1. **截图找人**：远端检测接口返回 `coordinate_system=xyxy_pixels_exif_corrected` 的人体框。单人时裁剪、编码并检索；多人时返回带编号的 `pedestrian_selection`，每个候选附 256px 预览图和提示「请明确回复选择编号，例如：选择2。」；无人时返回 `no_person`，提示重传。
2. **单人图检索**：编码查询图，在 `identity`/`feature` 上做余弦检索。要求查询特征与目标特征空间兼容（均启用、同为 cosine、维度一致、`object_type='person'`），否则直接报错而不是返回空结果。
3. **外观描述检索**：把文字编码到 Chinese-CLIP 文本空间，再在该 `feature_space_id` 对应的 `feature`/`sample`/`identity` 上做 pgvector 余弦检索。检索对象是样本管线为登记照片写入的 enrollment 特征（`sample.purpose='enrollment'`，只关联 `identity_kind='registered'` 且启用的身份），不在查询时重新编码照片，也不检索新轨迹特征；同一身份有多张登记照片时只保留最相似的一张。特征空间缺失、不兼容或登记特征为空时返回对应状态，不会编码文字或返回「无匹配」。

### 6.3 候选结构

每个轨迹检索候选包含：

- `identity_id` / `person_id`（前端兼容，等于 `identity_id`）、`identity_kind`（temporary/registered）、`display_no`、`name`、`label`（「登记身份」/「临时身份 #N」）、`employee_id`；
- `similarity`：余弦相似度，不是身份正确率；
- `image_base64`：预览图 Data URL；
- `first_seen_at` / `last_seen_at` / `occurrence_count`；
- `occurrences[]`：最多 5 条真实轨迹出现记录（`tracklet_id`、`source_id`、`camera`、`start_at`、`end_at`、`asset_id`、`access_url`）。

文本检索候选只返回登记身份，结构为：

- `identity_id` / `person_id`（等于 `identity_id`）、`identity_kind`、`display_no`、`name`、`label`、`employee_id`；
- `similarity`、`feature_id`、`sample_id`；
- `asset_id` / `access_url`：最相似的登记照片，通过 `/api/v1/business/assets/{asset_id}/content` 读取，不在响应中放 Base64；
- `first_seen_at` / `last_seen_at`；不包含 `occurrences`。

预览图只在配置了 `AGENT_MEDIA_ROOT` 时生成：路径必须解析到该根目录之下，内容类型和大小都受限；否则字段为空。临时身份没有姓名，模型不得编造。

### 6.4 边界

- 结果是「相似度排序」，没有校准阈值，首位不等于命中；提示词要求模型据此措辞。
- 只覆盖当前保留期内的已入库轨迹，不查实时摄像头，不给出实时位置。
- ReID 服务不可用时必须说明「未执行匹配」，不能说「没有匹配人员」。
- 描述检索不支持按时间、摄像头筛选，也不返回历史出现记录；它只覆盖已完成 Chinese-CLIP enrollment 特征写入的登记身份，未运行登记特征写入进程时返回 `empty_gallery`。

## 7. 会话记忆与图片资产

| 能力 | 默认上限 | 说明 |
| --- | --- | --- |
| 会话记忆 | 1000 个会话 × 20 条消息 | 进程内 `SessionMemoryStore`，重启即清空 |
| 图片资产 | 每会话 4 张、32MB，全局 256MB，TTL 1800 秒 | 保存上传图片，供追问复用 |
| 多人待选择 | 16 个会话，TTL 300 秒 | 保存原图与候选框 |
| 请求体 | 20MB | `MAX_REQUEST_BYTES` |
| prompt | 8000 字符 | `MAX_PROMPT_CHARS` |
| 单图 | 10MB、2500 万像素、单边 8192 | JPEG / PNG / WebP |

`DELETE /sessions/<session_id>/memory` 会同时清除记忆、待选择状态和图片资产。

## 8. HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/chat` | 非流式对话，返回完整 JSON |
| POST | `/chat/stream` | SSE 流式对话 |
| GET | `/tools` | 当前注册的工具及参数 Schema |
| GET | `/persons` | 已登记人员名单 |
| POST | `/reload_persons` | 重新加载熟人缓存 |
| DELETE | `/sessions/<session_id>/memory` | 清除该会话的记忆与图片 |
| GET | `/health` | 存活检查 |
| GET | `/ready` | 就绪检查：数据库 `SELECT 1` + 模型健康状态 |

请求体（`/chat`、`/chat/stream` 相同）：

```json
{
  "prompt": "今天张三去过哪些地方",
  "session_id": "可选，缺省由服务生成",
  "trace_id": "可选，用于日志串联",
  "image_base64": "可选，Base64 或 data URL"
}
```

`/chat` 响应在原有字段上追加 `session_id`，并返回 `X-Trace-ID` 响应头。

SSE 事件：

| event | data | 说明 |
| --- | --- | --- |
| `status` | `{"stage":"processing"}` / `{"stage":"generating"}` | 阶段提示 |
| `delta` | `{"text":"…"}` | 正文增量 |
| `result` | 结构化结果 | 图片检索、超分等业务数据 |
| `done` | `{"session_id","finish_reason","steps"}` | 正常结束 |
| `error` | `{"error","error_code"}` | 处理失败 |

响应头包含 `Cache-Control: no-cache`、`X-Accel-Buffering: no`（禁用 Nginx 缓冲）、`X-Trace-ID`。客户端提前断开时记录 `STREAM_INTERRUPTED`。

错误码：

| error_code | HTTP | 触发条件 |
| --- | --- | --- |
| `MISSING_PROMPT` | 400 | 缺少 prompt |
| `PROMPT_TOO_LONG` | 400 | prompt 超长 |
| `INVALID_TRACE_ID` / `INVALID_SESSION_ID` | 400 | 标识符格式非法 |
| `INVALID_IMAGE` / `UNSUPPORTED_IMAGE_FORMAT` | 400 | 图片无法解析或格式不支持 |
| `MULTIPLE_IMAGES` | 400 | 一次请求带多张图片 |
| `INVALID_JSON` | 400 | 请求体不是合法 JSON |
| `IMAGE_TOO_LARGE` / `IMAGE_DIMENSIONS_TOO_LARGE` | 413 | 图片字节、像素或边长超限 |
| `REQUEST_TOO_LARGE` | 413 | 请求体超限 |
| `INTERNAL_ERROR` | 500 | 未预期异常 |

## 10. 日志与可观测性

每次请求输出单行 JSON 事件到标准输出和 `agent.jsonl`：

- 请求级：`request_start`、`request_end`、`request_rejected`；
- Agent 级：`agent_start`、`agent_end`、`agent_action`；
- 模型与工具：`llm_call_end`、`tool_start`、`tool_end`；
- 图片：`image_asset_stored`。

日志写入 `.runtime-cache/service-stack/{api,vllm,sglang}/`，`agent.log` 可读、`agent.jsonl` 机器解析。图片内容在日志中以 `[image data omitted: N chars]` 替换，不落盘。

常用排查字段：`trace_id`、`session_id`、`elapsed_ms`、`steps`、`finish_reason`、`error_code`、工具名与耗时。

## 11. 数据表依赖

只读使用：`identity`、`identity_link`、`feature`、`feature_space`、`track_identity_assignment`、`tracklet`、`camera`、`sample`、`media_asset`、`vad`、`llm_report`、`episode`、`episode_tracklet_link`。文本检索通过 `feature`/`sample`/`identity` 关联读取登记照片特征，不再读取 `reid_target`。

服务不做数据库迁移，不自动建表，不写入业务数据；连接参数缺失或表结构不符时应显式报错，而不是降级成空结果。

## 12. 已知边界

- **两段式模型调用**：流式回答必须先完成整轮决策，首字延迟明显高于纯聊天；工具调用越多越慢。
- **工具描述开销**：系统提示词加 11 个工具 Schema 约 5k tokens，每次决策都会重发，可依赖服务商前缀缓存降低开销。
- **思考模式**：API 模式下若 `LLM_REMOTE_ENABLE_THINKING` 为空，会覆盖本地 `LLM_ENABLE_THINKING=false`，导致服务商侧思考开启、延迟成倍增加；需要关闭时应显式设为 `false`。
- **单进程状态**：记忆、图片资产、待选择会话都在进程内，重启丢失，且不支持多副本无会话粘滞的部署。
- **ReID 只认图不认人**：临时身份没有姓名；相似度不是身份确认，服务不会替用户认定某人是谁。
- **图片描述检索只覆盖已写入 Chinese-CLIP 特征的登记身份**；登记照片未编码、特征空间未注册或服务不可用时不返回候选。
- **无鉴权**：服务默认部署在内网，接口本身不做身份认证，需由网关或内网隔离保护。
