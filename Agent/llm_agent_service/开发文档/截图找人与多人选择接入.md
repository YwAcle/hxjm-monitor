# 截图找人与多人选择

第二步接入远端 `POST /v1/reid/person-crops`，沿用现有 CLIP-ReID 地址及配置，无需新增环境变量。通过新增 Agent 工具 `search_pedestrians_in_screenshot` 处理截图找人，原 `search_pedestrians_by_image` 继续用于已经裁好的单人图片。不会调用实时摄像头或轨迹接口。

## 聊天操作

1. 在聊天窗口上传截图，同时输入：“用这张监控截图在登记库找相似行人，返回前3个候选。”
2. 截图只检测到一人时，直接使用接口返回的特征查询登记库，不重复提取查询图特征。
3. 检测到多人时，系统返回候选编号、裁剪预览和框坐标，并停止工具循环，不让模型擅自选人。
4. 在同一 session_id 下回复“选择2”“2”或“第二个”，后端从保存的本次原图和候选框提取特征，返回相似登记人员。选人阶段不需要再次调用大模型。
5. 回复“取消”或“取消选择”清除待选择状态。上传任何新图片会清除该会话旧状态；清空会话记忆也同时清除。

未检测到行人时，不用整张背景图片做 ReID，提示重传或自行裁剪单人图。无效编号不发起检索，继续等待用户明确选择。前端刷新后只要保留相同 session_id、Agent 尚未重启且状态未过期，仍可继续；不同 session_id 不能互取截图。

只描述截图、数人或读取图片内容时，仍由视觉模型直接回答，不调用截图找人工具。

## 前端数据

继续使用 POST /chat 或 /chat/stream，参数仍为 prompt、image（或 multipart file）和 session_id。

普通接口通过 data 返回；SSE 通过 result 事件返回业务数据。多人待选择格式：

```json
{
  "type": "pedestrian_selection",
  "status": "selection_required",
  "source_asset_id": "本次截图唯一标识",
  "image_width": 1920,
  "image_height": 1080,
  "coordinate_system": "xyxy_pixels_exif_corrected",
  "candidates": [
    {"candidate_id": "1", "bbox": [120, 80, 300, 600], "confidence": 0.93, "image_base64": "data:image/jpeg;base64,..."},
    {"candidate_id": "2", "bbox": [500, 100, 680, 620], "confidence": 0.89, "image_base64": "data:image/jpeg;base64,..."}
  ],
  "top_k": 3,
  "message": "检测到多名行人，请明确回复选择编号，例如：选择2。编号仅对应本次截图，不是人员身份。"
}
```

前端可将 candidates 渲染为编号缩略图，点击后发送 prompt=选择2，并沿用 session_id。也可在截图上画框，但原图需先做 EXIF 方向校正，再按显示比例缩放 bbox。原图坐标右、下边界不包含在裁剪范围内。检测 confidence 不是身份相似度。

当前仓库后端已输出编号文本和上述结构化数据；本次未修改部署中的外部前端。现有前端即使没有点选控件，也可直接输入编号续接；若需显示裁剪预览，需处理 pedestrian_selection 的 result 事件。

选中并检索完成后，仍返回 type=pedestrian_search 的原候选结构，附 source_asset_id、selected_candidate_id。过期或没有待选择截图时返回 status=selection_expired，并提示重新上传；取消返回 status=cancelled。

## 状态与特征一致性

待选择截图仅放在当前 Agent 进程内存，不写数据库、磁盘或聊天历史。有效期5分钟，最多16个会话，图片 Base64 总字符上限32 MiB。达到容量时淘汰最旧状态，Agent 重启后状态失效；当前仅适合单 Agent 进程部署。图片预览与坐标可返回前端，日志继续隐藏 Base64。

后端先按 EXIF 校正原图，再以 PNG 发给检测服务。选人时对同一张图执行相同转换，并将服务器保存的 bbox 通过 multipart 传给 image-features，不重新检测、不接受模型编造的框。单人提取与后续登记特征仍须同一 feature_space_id；版本变化不混用向量。

## 验证

2026年10月21日，真实远程 YOLO/CLIP-ReID 与在线登记库联调：登记单人图直接返回3个候选；两张登记图组成的测试截图返回2个候选框；明确选择后返回3个登记候选；空白图返回 no_person。结果记录于 `.runtime-cache/reid-screenshot-live.json`，不纳入 Git。该验证未评估检测和身份检索准确率，也未验证浏览器展示及真实聊天模型自动选工具。

自动化覆盖 multipart 的 bbox、EXIF 校正、单人复用特征、多人停等、无人不查库、会话隔离、过期、容量淘汰、错误编号、新图替换、取消、清空会话，以及普通聊天和 SSE 的两轮续接。

代码更新后需要重启 Agent 生效。本次不自动重启模型或 Agent；既有模型决策耗时及 Agent 总预算限制仍适用。
