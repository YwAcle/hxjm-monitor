# 轨迹身份主动检索

图片及截图检索使用 CLIP-ReID HTTP 特征服务编码查询图，然后在新轨迹身份表中做 pgvector 余弦检索。Agent 只读取 `feature`、`identity`、`track_identity_assignment`、`tracklet`、`sample` 和 `camera`，不重新编码历史图片，不写身份关联，也不访问实时摄像头。

历史特征由样本管线写入。候选身份通常是 `identity_kind='temporary'` 的临时身份，没有姓名或工号；结果同时返回该身份在保留期内的真实轨迹出现记录（时间、摄像头、素材 ID）。

## 检索工具

- `search_pedestrians_by_image`：已裁好的单人图片通过 CLIP-ReID 提取 3072 维归一化特征，在 `feature.embedding` 中按余弦相似度检索，按身份取最相似的一条轨迹特征，默认返回前 5 个候选身份（最多 10 个）。每个候选带 `occurrences`，列出该身份最近的真实轨迹记录。
- `search_pedestrians_in_screenshot`：先调用截图检测接口；单人直接复用返回的特征检索；多人返回编号、裁剪预览和候选框等待用户明确选择，无人则提示重传。详细流程见[截图找人与多人选择接入](截图找人与多人选择接入.md)。
- `search_pedestrians_by_description`：调用远端 Chinese-CLIP 文本接口，把描述编码到登记照片所在的 `feature_space_id`，再在 `feature`/`sample`/`identity` 上按 pgvector 余弦相似度检索。检索对象是样本管线写入的 enrollment 特征（`sample.purpose='enrollment'`，只关联启用的 `identity_kind='registered'` 身份），不在查询时重新编码照片。登记特征为空时返回 `empty_gallery`；文本服务不可用时如实报错。
- `search_pedestrians_by_description_in_history`：同一个 Chinese-CLIP 文本空间，但检索对象是样本管线为 `sample.purpose='history'` 写入的轨迹裁剪图特征，因此候选是全部已入库历史轨迹图像，不限于已登记身份；未关联身份的轨迹 `name=null`，前端显示“未识别轨迹”。历史文本特征为空时返回 `empty_text_history`。

## 检索语义

查询特征与 `feature.feature_space_id` 必须完全一致；服务健康检查仍校验 3072 维、归一化和特征空间版本。检索只使用：

- `feature.state='ready'` 且未到期、向量非空；
- `tracklet.expires_at > now()`；
- `identity.enabled` 且未到期；
- `track_identity_assignment.valid_to IS NULL` 且未到期。

如果临时身份通过 `identity_link` 关联到已登记身份，候选会归并到已登记身份；当前没有有效关联，因此返回临时身份。`identity_kind` 和 `display_name` 会原样返回，`name=null` 时前端使用 `label`（例如“临时身份 #123”），Agent 不得编造姓名。

返回字段：

| 字段 | 含义 |
|---|---|
| `scope` | 固定 `identity_history`，表示历史轨迹身份检索 |
| `scanned_count` | 当前特征空间内可检索的历史特征数 |
| `compatible_count` | 有关联身份的身份数 |
| `candidates[].identity_id` | 新 `identity.id`；兼容字段 `person_id` 同值 |
| `candidates[].similarity` | 与身份最相似历史特征的余弦相似度，不是身份置信度 |
| `candidates[].occurrence_count` | 该身份在保留期内的轨迹总数 |
| `candidates[].image_base64` | 最近一条轨迹的裁剪图 data URL；未配置 `AGENT_MEDIA_ROOT`、文件缺失或媒体不可用时为 `null` |
| `candidates[].occurrences` | 最近最多 5 条轨迹：`tracklet_id`、`camera`、`source_id`、`start_at`、`end_at`、`asset_id`、`access_url` |

`occurrences` 的顺序是最后出现时间倒序。`access_url` 是后端素材读取接口的相对路径，是否需要鉴权由前端当前登录态处理。候选卡片优先直接显示 `image_base64`；为 `null` 时前端可再用 `asset_id` 换取短期 playback ticket。

### 文本检索语义

文本检索与图片检索使用不同的特征空间，不能互相比较：

- 文本向量为 Chinese-CLIP 512 维；`feature_space_id` 必须与 `/health.text_reid` 返回的 `fs-<64位摘要>` 完全一致。
- 只读取 `feature.state='ready'`、未到期、关联 `sample.purpose='enrollment'` 且 `sample.available` 的向量；
- 只返回启用的 `identity_kind='registered'` 身份；临时身份和轨迹出现记录不会出现在文本结果中；
- 同一身份有多张登记照片时，按相似度只保留最大的一条，并返回对应 `feature_id`、`sample_id`、`asset_id`。

登记照片特征由样本管线写入：`video_analysis` 在 `VIDEO_SAMPLES_ENABLED=true` 时随采样进程轮询后端 `/samples/pending?purpose=enrollment`，用 `/v1/reid/text-reid-image-features` 编码后注册 `feature` 和 `feature_contribution`（默认 `VIDEO_SAMPLES_TEXT_ENABLED=true`，同时写 CLIP-ReID 图片空间）。也可单独运行 `python/video_analysis/enrollment_text_worker.py` 只写文本空间。未开启样本管线、未运行worker或尚未写入任何特征时，文本检索返回 `empty_gallery`。

历史轨迹裁剪图由同一样本管线写入：实时裁剪图在确认入库后直接编码到两个空间；文本空间还轮询 `/samples/pending?purpose=history` 补齐此前未编码的历史裁剪图，注册带 `tracklet_id`、不带 `identity_id` 的 `feature`，不写入 `track_identity_assignment`。也可单独运行 `enrollment_text_worker.py` 的 history 模式（`ENROLLMENT_TEXT_SAMPLE_PURPOSE=history`）。后端 `/samples/pending` 支持 `purpose=enrollment|history`；两种模式各自只处理本用途的样本，可同时运行。历史特征随样本到期，没有历史特征时 `search_pedestrians_by_description_in_history` 返回 `empty_text_history`。CLIP-ReID 图片检索仍然只读 3072 维空间，不受影响。

文本结果的 `scope` 为 `registered_identity`，候选字段为 `identity_id`/`person_id`、`identity_kind`、`display_no`、`name`、`label`、`employee_id`、`similarity`、`feature_id`、`sample_id`、`asset_id`、`access_url`、`first_seen_at`、`last_seen_at`，不含 `image_base64` 和 `occurrences`。

文本检索状态：

| 状态 | 含义 |
|---|---|
| `missing_description` / `description_too_long` | 描述为空或超过本地/模型长度限制，未调用文本编码 |
| `feature_space_missing` | 数据库尚未注册该 `feature_space_id` |
| `feature_space_incompatible` | 空间未启用、度量不是 cosine、对象类型不是 person 或维度不一致 |
| `empty_gallery` | 该空间没有可用的登记照片特征 |
| `no_identity_candidates` | 特征存在但没有关联到有效登记身份 |
| `ok` | 已按余弦相似度排序返回候选 |

历史图像文本检索的 `scope` 为 `history_samples`，其余状态含义相同，另有：

| 状态 | 含义 |
|---|---|
| `empty_text_history` | 该空间没有可用的 history 样本特征 |
| `no_text_candidates` | 历史特征存在但没有可返回的轨迹候选 |

历史候选字段为 `tracklet_id`、`sample_id`、`feature_id`、`asset_id`、`access_url`、`image_base64`（受 `AGENT_MEDIA_ROOT` 限制）、`similarity`、`identity_id`/`person_id`（未识别时为 `null`）、`identity_kind`、`display_no`、`name`、`label`、`employee_id`、`occurred_at`、`occurrence_count` 和单条 `occurrences`。每条轨迹只保留最相似的一张裁剪图。

## 配置与验证

根目录 `.env` 保留以下配置即可，不需要选择 ReID 后端或配置本地权重：

```dotenv
REID_FEATURE_BASE_URL=http://100.127.237.7:28024
REID_TIMEOUT_S=30
# 可选：固定服务健康检查返回的完整特征空间版本
# REID_FEATURE_SPACE_ID=clipreid-rn50-<版本摘要>
# 可选：固定 Chinese-CLIP 文本特征空间和文本契约
# REID_TEXT_FEATURE_SPACE_ID=fs-<64位定义摘要>
# REID_TEXT_CONTRACT_ID=fs-<64位定义摘要>-text-v1
REID_TEXT_MAX_CHARS=200
# 历史轨迹裁剪图根目录：与 media_asset.storage_key 拼接读取候选预览图
# 仅当 Agent 能直接读取素材存储目录时填写；留空则不返回 image_base64
AGENT_MEDIA_ROOT=/data/nfs_storage/hxjm_datas
```

`AGENT_MEDIA_ROOT` 只用于读取候选卡片预览图，不写文件。路径会与 `storage_key` 拼接并校验必须位于该根目录内；单张图超过 200 KB、类型不是 JPEG/PNG/WebP 或文件不存在时跳过，不影响检索结果。

修改配置或代码后需重启 Agent；不自动重启现有服务。

只读验证脚本不写数据库，也不依赖聊天模型。省略 `--image` 时取一条历史特征做数据库自检；提供图片时走完整 CLIP-ReID 编码和 pgvector 检索：

```bash
# 加载共享配置；不直接 source 任意 .env 内容。
source scripts/load_env.sh
load_env_defaults .env

# 数据库自检：第一条历史特征应检索到它所属身份
python scripts/verify_local_reid.py

# 用实际图片验证完整链路
python scripts/verify_local_reid.py --image /本仓库内/行人图片.jpg --expect-identity-id <可选身份UUID>
```

远端接口、连通性和特征兼容要求见 [CLIP-ReID接入说明](CLIP-ReID接入说明.md)。服务不可达时明确报错，不使用其他模型替代，也不把失败解释为“没有匹配人员”。

## 特征、缓存与保留期

查询图每次由同一 CLIP-ReID 服务编码，校验健康状态、3072 维特征和 `feature_space_id`。历史特征直接使用数据库向量，不再逐张编码裁剪图，因此检索耗时不再随历史记录数线性增加。

历史特征、样本、轨迹和身份都有保留期；过期后不再出现在结果中。当前样本按发生时间保留 7 天，`expires_at` 由样本管线写入。未关联到有效身份的轨迹不会作为候选返回。

## 聊天请求与结果

向 `POST /chat` 或 `POST /chat/stream` 提交 `prompt`、`image`（或 multipart 的 `file`）和 `session_id`。

- 单人图片：“用这张单人图片找相似的人，并告诉我他最近出现的时间和摄像头。”
- 监控截图：“用这张截图找相似行人。多人时在同一会话回复“选择2”。
- 外观描述：“在登记照片中找穿红色上衣、背黑色包的人。”
- 全量历史画面：“在所有历史监控画面里找穿红色上衣、背黑色包的人。”

图片由执行器从本次上传请求强制注入工具，不允许模型生成 Base64。除截图待选择状态外，不保留图片供下一轮检索引用。

普通 `/chat` 返回 `data.type=pedestrian_search`，`scope=identity_history`，候选在 `data.candidates` 中，每项包含 `identity_id`、`identity_kind`、`display_no`、`name`、`label`、`similarity`、`image_base64`、`occurrence_count` 和 `occurrences`。SSE 通过 `result` 事件返回业务数据。`image_base64` 只在返回给前端的业务数据中携带，写入 JSONL 和发送给大模型前会按字段名替换为摘要。

## 边界与检查

- 临时身份不是已确认身份；相似度不是身份确认概率，不能把首位当作命中。
- `empty_history` 表示当前保留期内没有可检索特征，不能据此排除某人。
- `feature_space_missing` 或 `feature_space_incompatible` 表示特征版本不匹配，不能报“没有匹配人员”。
- 文本检索的 `empty_gallery`、`empty_text_history`、`feature_space_missing`、`feature_space_incompatible` 只表示特征未写入或空间不可用，不等于该人员或轨迹不存在；需先开启 `VIDEO_SAMPLES_ENABLED=true` 的样本管线（或按用途运行 `enrollment_text_worker.py`）。
- 结果只覆盖已入库且未过期的轨迹，不表示实时位置，也不代表轨迹完整。
- 自身检索只能验证编码和数据库排序链路一致性；跨摄像头、跨姿态检索质量需要另外评估。
- 自动化测试覆盖特征空间校验、候选映射、轨迹记录、截图选择，以及普通聊天和 SSE 返回；真实远端、数据库和浏览器展示需单独联调。
