# 登记库主动行人检索

图片及截图检索统一使用 CLIP-ReID HTTP 特征服务。Agent 只读 `reid_target` 的有效记录，对查询图片和登记照片重新生成同一特征空间的特征，不读取或修改原库向量，不写入身份关联。不访问实时摄像头，也不把登记照片当作历史出现证据。

## 检索工具

- `search_pedestrians_by_image`：已裁好的单人图片通过 CLIP-ReID 提取3072维归一化特征，在最多2000条有效登记记录中计算余弦相似度，默认返回前5个候选，最多10个。没有校准的身份确认阈值，返回的是外观相似候选，不是确定身份。
- `search_pedestrians_in_screenshot`：先调用截图检测接口；单人直接复用返回的特征检索，多人返回编号、裁剪预览和候选框等待用户明确选择，无人则提示重传。详细流程见[截图找人与多人选择接入](截图找人与多人选择接入.md)。
- `search_pedestrians_by_description`：调用远端 Chinese-CLIP 文本接口，把衣着、颜色、携带物品等描述编码为文本向量，再用同一服务的 Chinese-CLIP 图片接口编码登记照片，在最多2000条有效登记记录中按余弦相似度排序，返回候选和 `similarity`。文本与登记图必须处于同一 `feature_space_id`；它与 CLIP-ReID 的3072维图片空间完全隔离，二者向量不互相比较。没有校准阈值，`status=ok` 只表示已排序，不表示命中。

描述超过 `REID_TEXT_MAX_CHARS`（默认200）时返回 `description_too_long`，不调用远端；远端 tokenizer 上限更短时返回同一状态，要求用户精简描述，不静默截断。空库返回 `empty_gallery`，全部登记图不可解码返回 `no_valid_images`，都不会被解释为“没有此人”。

## 配置与验证

根目录 `.env` 保留以下配置即可，不需要选择 ReID 后端或配置本地权重：

```dotenv
REID_FEATURE_BASE_URL=http://100.127.237.7:28024
REID_TIMEOUT_S=30
# 可选：固定服务健康检查返回的完整特征空间版本
# REID_FEATURE_SPACE_ID=clipreid-rn50-<版本摘要>
# 可选：固定 Chinese-CLIP 文本特征空间和文本契约
# REID_TEXT_FEATURE_SPACE_ID=chinese-clip-vit-b16-<版本摘要>
# REID_TEXT_CONTRACT_ID=chinese-clip-vit-b16-<版本摘要>-text-v1
REID_TEXT_MAX_CHARS=200
```

安装 Agent 的常规依赖即可，无需本地推理运行时或权重下载步骤。修改配置或代码后需重启 Agent；不自动重启现有服务。

只读验证图片检索、不依赖聊天模型的脚本保留原文件名，内部只调用 CLIP-ReID，不再接受后端选择参数。从仓库根目录执行：

```bash
# 加载共享配置；不直接 source 任意 .env 内容。
source scripts/load_env.sh
load_env_defaults .env

# 默认用首张登记照片作自身检索；请使用 Agent 实际运行的 Python。
python scripts/verify_local_reid.py
# 或传入实际查询图片：
python scripts/verify_local_reid.py --image /本仓库内/行人图片.jpg

# 验证文字检索链路（不经过聊天模型）：
python scripts/verify_text_reid.py --description "穿红色上衣、背黑色双肩包的人" --top-k 5
```

远端接口、连通性和特征兼容要求见 [CLIP-ReID接入说明](CLIP-ReID接入说明.md)。服务不可达时明确报错，不使用其他模型替代，也不把失败解释为“没有匹配人员”。

## 特征与缓存

旧库的模型名称不能证明与远端特征空间一致，因此登记照片和查询图片都由同一 CLIP-ReID 服务编码。每次查询校验健康状态、3072维特征和 `feature_space_id`，各图片响应也必须保持相同版本。

登记特征按特征空间、人员 ID 和图片内容摘要缓存在 Agent 进程内；登记图片变化、人员停用/移除或模型版本变化后旧缓存被淘汰。Agent 重启后需要重新编码。首次查询需串行编码登记照片，可能耗时较长。缓存不写数据库，不需要额外缓存服务。

## 聊天请求与结果

向 `POST /chat` 或 `POST /chat/stream` 提交 `prompt`、`image`（或 multipart 的 `file`）和 `session_id`。

- 单人图片：“用这张单人图片找相似的登记行人，返回前3个候选。”
- 监控截图：“用这张截图在登记库找相似行人。”多人时在同一会话回复“选择2”。
- 外观描述：“在登记照片中找穿红色上衣、背黑色包的人。”

图片由执行器从本次上传请求强制注入工具，不允许模型生成 Base64。除截图待选择状态外，不保留图片供下一轮检索引用。

普通 `/chat` 返回 `data.type=pedestrian_search`，候选在 `data.candidates` 中，每项包含 `person_id`、`name`、`employee_id`、`image_base64` 和 `similarity`。图片与文字检索都按余弦相似度排序，`search_type` 分别为 `image` 和 `text`，`method` 分别为 `remote_clipreid` 和 `remote_chinese_clip_text`。姓名属于候选登记档案，不是对查询图片人物身份的确认。

SSE 通过 `result` 事件返回业务数据，前端需处理该事件才能显示候选照片或多人裁剪预览。Base64 保留在前端业务结果中，不加入工具观察文本或日志。

## 边界与检查

- `gallery_truncated=true` 表示只搜索了部分登记记录，不能当作全库结果。
- 不支持时间或摄像头过滤，不查询历史出现记录，也不确认当前在场情况。
- 自身检索只能验证编码和链路一致性；跨摄像头、跨姿态检索质量需要另外评估。
- 自动化测试覆盖图库排序、范围截断、特征校验、缓存、截图选择，以及普通聊天和 SSE 返回；真实远端、数据库和浏览器展示需单独联调。
